## 디자인 리드 (스킬 0.B)

> Reading this as: 데스크탑 제품 UI(무한 캔버스 워크스페이스) for 프로젝트를 병행하는 개인 작업자, with a "불투명한 물체가 사용자 배경 위에 놓여 있다" 언어, leaning toward 자체 CSS 토큰 + 따뜻한 뉴트럴 한 벌 + 번트 앰버 액센트 하나 + Tabler 아이콘.

## 고른 방향과 이유

**"위젯은 불투명한 물체다. 유리가 아니다."**

브리프 제약 2번이 방향을 결정했다 - 배경이 밝은 사진 / 어두운 사진 / 밝은 단색 / 어두운 단색 넷 다 가능하고, **UI 한 벌이 넷 다에서 성립해야 한다.**

- 반투명 표면은 배경 휘도를 그대로 물려받는다. 사진 배경에서 글자 대비가 배경 사진의 밝은 얼룩마다 달라진다. 네 가지 배경을 한 벌로 못 버틴다.
- 그래서 **텍스트를 이고 있는 면은 전부 불투명**으로 고정했다. 반투명은 어디에도 안 썼다.
- 대신 배경과 분리되는 문제는 **이중 테두리**로 푼다. 안쪽 1px은 테마의 잉크색(같은 극성 배경에서 분리), 바깥 1px 헤일로는 테마의 밝은색(사진의 어두운 부분에서 분리), 거기에 배경 색조로 틴트한 그림자 3겹. 셋이 항상 켜져 있다. `.surf` 한 클래스에 들어 있다.

감성은 투명도가 아니라 다른 데서 낸다: 배경 사진이 넓게 보이도록 위젯을 띄엄띄엄 놓았고, 표면은 순백이 아닌 따뜻한 뉴트럴, 그림자는 넓고 부드럽고 따뜻하게 틴트, 화면 전체에 고운 그레인. 그리고 공간 타일을 누르면 배경·이름·명암 극성이 통째로 바뀐다 - 파는 것이 "프로젝트 전환"이라 전환 자체를 보여주는 게 감성 장치다.

**Calm Tech는 "위젯 헤더를 평소에 숨긴다"로 구현했다.** 위젯 헤더(이름·최대화·닫기)는 30px 자리를 항상 차지하되 내용은 opacity 0이고, hover / focus-within에서만 나타난다. 자리를 유지하니 레이아웃이 안 튄다. Memo 위젯 하나만 `chrome-on`으로 고정해서 정적 화면에서도 패턴이 보이게 했다. 독의 Arrange 버튼도 같은 원리 - 선택된 게 있을 때만 의미가 생기는 컨트롤이다.

**셸은 전부 띄워 놨다.** 레일도 독도 패널도 창 가장자리에 붙지 않고 14px 여백을 두고 뜬다. 배경이 창 네 변에 다 닿는다. "물체가 배경 위에 놓여 있다"를 셸까지 일관되게 밀기 위한 결정이다.

## 폰트 / 색 / 라디우스

**폰트** - `Instrument Sans` (400/500/600/700) + `JetBrains Mono` (숫자 전용).
Inter 금지 조항 때문만이 아니라, 작은 UI 크기에서 형태 구분이 좋고 Inter보다 약간 인간적인 그로테스크라 골랐다. 세리프는 안 썼다 - 근거가 없다(스킬 4.1 세리프 규율). 위계는 크기가 아니라 굵기·색으로 잡았다: 제목 600, 본문 400, 메타 500 + `--text-3`. 가장 큰 글자는 타이머 42px 하나뿐이고 `-0.035em` 음수 트래킹을 넣었다. 숫자는 전부 mono + `tabular-nums`(타이머·줌 배율·볼륨).

**색** - 액센트 **번트 앰버 하나**. 라이트 `#A9581B`, 다크 `#E9A75F`. 채도 71% / 76%로 둘 다 80% 미만. 그레이는 따뜻한 계열 **한 벌**만(차가운 그레이 혼용 없음). AI 퍼플 0, 네온·글로우 0.

액센트가 쓰이는 곳: Arrange 기본 버튼, 활성 공간 표시 막대, 타이머 진행 막대, 체크된 체크박스, 브라우저 로딩 막대, 페이더 캡, 포커스 링, Retry. 그 외 어디에도 유채색이 없다.

- 대비 검증(계산치): 라이트 본문 15.7:1, 보조 6.6:1, 최하위 4.7:1. 다크 14.2 / 6.6 / 5.1. 기본 버튼 텍스트 라이트 4.9:1, 다크 8.9:1. hover 상태는 극성에 따라 어두워지거나 밝아지는 `--accent-hover`를 따로 둬서 hover에서 대비가 떨어지지 않게 했다.
- 순수 `#000` / `#fff` 없음. 라이트 표면 `#F7F6F3`, 다크 표면 `#201E1B`.
- **에러 색을 안 썼다.** 액센트 일관성 락을 지키려면 두 번째 색조를 넣을 수 없다. 대신 Memo의 에러는 아이콘(alert) + 명시적 문장("Save failed.") + 테두리를 진하게 한 스트립으로 표현했다. 색만으로 의미를 나르지 않으니 접근성상으로도 문제가 없다. 이건 의도적 결정이고, 실제 제품에서는 시맨틱 레드를 따로 두는 게 맞다고 본다.

**라디우스** - 3단 스케일, 문서화된 규칙:
`16px = 면(위젯·레일·독·패널)` / `8px = 컨트롤(버튼·인풋·탭·공간 타일)` / `4px = 인라인 마크(체크박스·칩·페이더 캡·진행 막대)`.
전부 4의 배수, 예외 없음. 원형(50%)은 한 군데도 안 썼다 - 페이더 캡도 둥근 사각으로 만들어서 락을 유지했다.

**그림자** - 순수 검정 금지. 라이트는 `rgba(46,38,28,.x)`로 배경 색조에 맞춰 따뜻하게 틴트, 다크는 그림자가 안 보이므로 상단 1px 내부 하이라이트로 모서리를 세운다.

## 버린 대안

**1. 프로스티드 글래스 셸 (제일 먼저 버렸다)**
"사용자가 배경을 고른다" + "UI가 그 위에 얹힌다"를 들으면 제일 먼저 나오는 답이고, 그래서 버렸다. 두 가지 이유:
- 기능적 이유가 더 크다. `backdrop-filter`는 배경 휘도를 그대로 물려받는다. 어두운 사진 위 밝은 유리 패널은 성립하지만, 대비 높은 사진(밝은 하늘 + 어두운 지면)에서는 같은 패널 안에서 글자 대비가 위아래로 달라진다. 위젯 4~6개가 동시에 떠 있는 상태에서 각각 다른 배경 조각을 물고 있으면 한 벌로 관리가 안 된다.
- 스킬 0.D가 "generic glassmorphism on everything"을 LLM 기본값으로 지목한다.
유리는 **어디에도 안 썼다.** 반투명은 위젯 헤더 페이드(opacity 전환)뿐이고 그건 표면이 아니라 콘텐츠다.

**2. 위젯 종류별 색 코딩**
Memo=초록, Todo=파랑 식으로 위젯 타입마다 색을 주는 안. 캔버스에서 위젯을 빨리 찾는 데는 확실히 유리하다. 버린 이유: 액센트 일관성 락이 깨진다. 6가지 색이 사용자가 고른 사진 배경 위에 동시에 떠 있으면 배경이 무엇이든 화면이 지저분해지고, "사용자의 배경이 주인공"이라는 방향과 정면으로 충돌한다. 대신 **아이콘 + 이름**으로 구분한다(헤더에 위젯 타입 아이콘).

**3. 상단 툴바 + 좌측 사이드바 (일반적인 앱 셸)**
Calm Tech 원칙 위반. 상단 툴바는 항상 화면 상단 전체를 먹는다. 대신 60px 레일 하나(공간 전환 = 제품 축 1번이니 이건 상시 노출할 값어치가 있다)와 하단 독 하나로 줄였고, 둘 다 띄워 놨다.

**4. 배경·주변음 패널 분리**
원래 배경 패널과 주변음 믹서를 각각 열리는 팝오버로 두려 했다. 정적 시안에서 팝오버 두 개가 동시에 열려 있으면 어수선하고, 무엇보다 둘 다 "이 공간의 분위기"라는 같은 설정 묶음이다. Atmosphere 패널 하나에 Background / Sound 두 그룹으로 합쳤다.

## 화면에 넣은 것

- 위젯 5개: **Browser**(780×500, 로딩 상태) / **Memo**(헤더 노출, 에러 상태) / **Timer**(포커스 세션 진행 중) / **Todo**(폼) / **Column**(빈 상태). Todo·Column은 선택 상태(액센트 아웃라인)로 두고 독에 "2 selected + Arrange"가 뜬다.
- 브라우저 위젯 안 페이지 영역은 **불투명 회색 판 하나**. div로 가짜 사이트 안 만들었다. 로딩만 상단 3px 액센트 막대로 표시.
- 상태 4종: 로딩(Browser) / 빈(Column) / 에러(Memo) / 폼(Todo, 라벨이 인풋 위, placeholder를 라벨로 안 씀).
- 줌은 진짜로 동작한다. 독의 +/-가 위젯 레이어 `transform: scale()`을 바꾸고 배율 표시가 따라간다. 배경은 안 움직인다(제약 3번).
- 공간 타일 4개 + 새 공간. 각 타일은 그 공간의 배경 미니어처를 그린다. 누르면 배경·이름·명암 극성이 같이 바뀐다.
- 밝음/어두움: Atmosphere 패널의 Light/Dark 세그먼트, 또는 배경 스와치 4개(밝은 사진 / 밝은 단색 / 어두운 사진 / 어두운 단색). 넷 다 눌러서 UI 한 벌이 버티는지 확인할 수 있다.
- 아이콘은 Tabler 지오메트리를 SVG 스프라이트로 인라인(단일 파일이라 npm 설치 경로가 없다). stroke-width 2로 전역 통일. 직접 그린 장식 SVG 없음.

## 프리플라이트 (스킬 14장, criteria.md의 "버린다" 항목 제외)

기계 검사(grep) 통과:
- 엠대시 `—` / 엔대시 `–` **0개**
- 중간점 `·` **0개**
- 순수 `#000` / `#fff` **0개**
- 퍼플·바이올렛·인디고 계열 **0개**
- `border-radius` 전부 토큰 3종만 사용, 원형 0
- `100dvh` 사용, `h-screen` 없음
- `prefers-reduced-motion: reduce` 블록 존재
- 태그 균형 확인, JS `node --check` 통과

수동 확인:
- 테마 락: 명암 극성은 루트 `data-theme` 하나로 전환. 화면 일부만 반전되는 구간 없음
- 색 락: 액센트 1개, 등장 위치 8곳 전부 같은 토큰
- 모양 락: 16 / 8 / 4 문서화된 3단, 예외 없음
- 버튼 대비: 기본 버튼 라이트 4.9:1 / 다크 8.9:1, hover 6.0:1 / 9.1:1
- 폼 대비: 라벨 6.6:1, placeholder는 `--text-3`(라이트 4.7:1 / 다크 5.1:1), 포커스 링은 액센트 2px + offset
- `:active` 촉감: 모든 버튼 `translateY(1px)`
- 빈 / 로딩 / 에러 상태 전부 존재
- 3등분 동일 카드 없음(위젯 5개가 전부 다른 크기·비율)
- 장식용 상태 점 0, 장식용 헤어라인 그리드 0, 긴 목록에 위아래 테두리 둘 다 없음(Todo는 행 테두리 자체를 안 씀)
- 모션: 자동 루프 0. hover 페이드 / :active / 줌 전환 세 가지뿐이고 셋 다 이유를 한 문장으로 댈 수 있다(컨트롤 노출 / 누름 피드백 / 배율 변경)
- `useEffect` 클린업: React가 아니라 해당 없음. 스크롤 리스너·타이머·rAF 없음. 등록한 리스너는 전부 영구 UI 요소에 붙어 있어 해제 대상이 아니다

건너뛴 항목(criteria.md "버린다" - 랜딩페이지 전용): 히어로 규칙 전부, 로고월, CTA 의도 중복, 아이브로우 개수, 스플릿 헤더, 지그재그 캡, 벤토 셀 개수, 섹션 레이아웃 반복, 마퀴, GSAP 스크롤, picsum 이미지 전략, 인용구, 가짜 인물·회사명, 디자인 시스템 맵.

## 알려진 한계

- 배경 사진은 picsum URL이다. 오프라인이면 그 레이어만 안 그려지고 아래 깔아둔 그라디언트가 대신 보인다(배경 레이어를 3중으로 쌓아 뒀다). 사진 위에는 극성 고정용 스크림을 덮어서, 어떤 사진이 와도 밝은 배경은 밝게 어두운 배경은 어둡게 유지된다.
- 위젯은 절대 좌표로 배치했다. 1440×880 근처를 기준으로 잡았고, 창이 그보다 작으면 캔버스가 잘린다(무한 캔버스라 잘리는 게 맞는 동작이다).
- 공간을 바꿔도 위젯 내용은 그대로다. 정적 시안이라 배경·이름·극성만 바꾼다.
