## 1. 이 디자인이 뭘 하려는 건가

**위젯은 유리가 아니라 불투명한 물체다. 사용자가 고른 배경 위에 놓여 있다.**

반투명 표면은 배경 휘도를 그대로 물려받는다. 이 앱은 배경이 네 가지(밝은 사진 / 어두운 사진 / 밝은 단색 / 어두운 단색)라 반투명으로는 한 벌이 성립하지 않는다. 사진의 밝은 얼룩마다 글자 대비가 달라진다.

- **글자를 이고 있는 면은 전부 불투명.** 반투명은 어디에도 안 쓴다
- 배경과 분리되는 문제는 **이중 테두리 + 틴트 그림자**로 푼다 (아래 4장)
- 감성은 투명도가 아니라 다른 데서 낸다 — 위젯을 띄엄띄엄 놓아 배경이 넓게 보이게, 표면은 순백이 아닌 따뜻한 뉴트럴, 그림자는 넓고 부드럽고 따뜻하게, 화면 전체에 고운 그레인
- **명암 극성은 배경이 정한다.** 공간을 고르면 배경·이름·극성이 한 번에 바뀐다. 그림과 토큰이 갈라질 수 없는 구조여야 한다 (이게 지금 앱의 9-2 버그다)

## 3. 글자

| 역할 | 값 | 토큰 |
|---|---|---|
| UI | Instrument Sans 400 / 500 / 600 / 700 | `--font-ui` |
| 숫자 | JetBrains Mono + `tabular-nums` (타이머·줌 배율·볼륨) | `--font-mono` |
| 세리프 | 안 쓴다 (근거 없음) | |

가변 축 하나(`wght` 400~700)로 네 굵기를 다 낸다. 한글은 Instrument Sans에 없으므로
스택에서 시스템 한글 글꼴로 떨어진다. **테마마다 글꼴이 갈리지 않는다** — 이전에는
Paper 테마가 UI 전체를 손글씨(Bradley Hand)로 그렸다.

- **위계는 크기가 아니라 굵기·색으로.** 제목 600 / 본문 400 / 메타 500 + `--text-3`
- 큰 글자에만 음수 트래킹. 타이머 42px에 `-0.035em`
- 라벨은 양수 트래킹 `.04em` ~ `.06em`

**스케일 6단.** 이 여섯 말고는 안 쓴다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--text-micro` | 10px | 대문자 트래킹 라벨·뱃지·단축키 |
| `--text-meta` | 11px | 메타·보조 |
| `--text-ui` | 12px | UI 기본 — 버튼·행·입력·탭 |
| `--text-body` | 14px | 본문·카드·메모 |
| `--text-title` | 17px | 위젯·패널 제목 |
| `--text-display` | 34px | 타이머·큰 숫자 |

작은 쪽이 1px씩 촘촘한 이유: 위계를 크기가 아니라 굵기·색으로 잡으므로 UI 대부분이
10~14px 안에 산다. 큰 쪽은 역할이 하나씩이라 사이가 넓다.

**시안의 11px 하한을 안 따르고 10px을 둔 이유**: 지금 앱에서 10px 이하가 76곳이고
전부 대문자 트래킹 라벨이다. 시안은 위젯 5개짜리 정적 화면이라 이 밀도가 없었다.
10px은 대문자 트래킹 라벨 전용으로만 쓴다.

⚠️ **오프라인 앱이라 woff2를 번들해야 한다.** CDN 링크로 두면 패키징본에서 시스템 폰트로 조용히 떨어진다.

## 4. 표면 · 모양

**라디우스 3단.** 이 셋 말고는 안 쓴다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--radius-surface` | 16px | 위젯·패널·독 |
| `--radius-control` | 8px | 버튼·입력·탭·주소창 |
| `--radius-mark` | 4px | 체크박스·색 마크·작은 표식 |

**위젯 표면 (`.surf`) — 세 겹이 항상 같이 켜져 있다.**

```css
box-shadow:
  0 0 0 1px var(--edge-strong),   /* 안쪽: 잉크색. 같은 극성 배경에서 분리 */
  0 0 0 2.5px var(--halo),        /* 바깥: 밝은색. 사진의 어두운 부분에서 분리 */
  0 1px 2px rgba(46,38,28,.10),   /* 그림자 3겹, 배경 색조로 틴트 */
  0 10px 22px -8px rgba(46,38,28,.20),
  0 28px 56px -26px rgba(46,38,28,.30);
```

- **그림자는 순수 검정을 쓰지 않는다.** 배경 색조로 틴트한다. 지금 앱은 7종 전부 `rgba(0,0,0,…)`이라 밝은 테마에서 회색 얼룩이 된다
- 광원 방향은 하나. 전부 위에서 아래

**그림자 토큰.** 색조는 테마가 자기 배경에서 뽑아 `--shadow-tint`(`r, g, b`)로 덮어쓴다.

| 토큰 | 쓰는 곳 |
|---|---|
| `--shadow-lift` | 바닥에 붙어 있는 것 — 행·카드·입력 |
| `--shadow-float` | 떠 있는 것 3겹 — 위젯·패널·독·팝오버 |
| `--lip` | 면의 윗변에 닿는 빛 1px |

**스페이싱 7단.** `2 / 4 / 6 / 8 / 12 / 16 / 24`px. Tailwind 눈금으로 `0.5 / 1 / 1.5 / 2 / 3 / 4 / 6`.
그 사이 값(`5` `7` `9` `10` `14`)은 안 쓴다 — 시안이 쓴 임의값들이 여기로 반올림된다.
셸이 창 가장자리에서 띄는 14px만 예외고, 그건 여백이 아니라 5장의 배치 규칙이다.

## 5. 배치

- **셸은 창 가장자리에 붙지 않는다.** 14px 여백을 두고 뜬다. 배경이 창 네 변에 다 닿는다
- **캔버스는 비대칭, 셸은 격자.** 위젯은 자유 좌표라 구도가 저절로 비대칭이 된다. 셸은 매일 8시간 쓰는 도구라 좌표가 흔들리면 안 된다
- 팝오버는 **화면 안으로 접는다.** 지금 앱의 Add Widget 팝오버가 창 밖으로 잘리는 버그가 있다

## 6. 움직임 · 상태

**MOTION_INTENSITY 3.** 이 앱에서 움직이는 건 사용자다 — 줌·팬·드래그. 그 위에 등장 애니메이션을 얹으면 사용자 조작과 경쟁한다.

- **자동 재생 루프 0개.** 트랜지션은 hover / `:active` / 줌 배율 변경 세 곳뿐
- `prefers-reduced-motion` 필수. 지금 앱은 0곳이고 배경 글로우가 11초 주기로 계속 돈다
- **포커스 링 필수.** 지금 앱은 `focus-visible`이 0곳이다

**Calm Tech = 위젯 헤더를 평소에 숨긴다.** 헤더(이름·최대화·닫기)는 30px 자리를 항상 차지하되 내용은 `opacity: 0`이고 `hover` / `focus-within`에서만 나타난다. 자리를 유지하니 레이아웃이 안 튄다.

**모든 위젯·패널이 가져야 하는 상태 네 개** — 지금 앱은 하나도 없다.

| 상태 | 규칙 |
|---|---|
| 빈 | 어떻게 채우는지 알려준다. "No tasks in this space / Add one here, or drag a checked line out of a memo." |
| 로딩 | 최종 레이아웃 모양의 스켈레톤. 원형 스피너 금지 |
| 에러 | 폼은 인라인, 그 외는 위젯 안에. 무엇이 잘못됐고 어떻게 고치는지. "Save failed. / Retry" |
| 촉감 | `:active`에 `translateY(1px)` 또는 `scale(.98)` |

## 7. 금지

- **엠대시 `—`.** UI 문자열 어디에도. 하이픈을 쓴다. 지금 앱은 공간 부제가 문자 그대로 `—`다

- 두 번째 액센트 색
- 순수 검정 그림자 · 순수 `#000` / `#fff`

- 손으로 그린 SVG 아이콘 — 아이콘 라이브러리를 쓴다
