## D-072 (2026-08-22) 앱 위젯 재작업 — 창 레벨 −1 폐기, 리사이즈는 창 모서리로
실사용에서 나온 문제들: ⓐ앱이 위젯 자리가 아니라 화면 가득 뜬다 ⓑ데스크로 못 돌아온다 ⓒ위젯이 "waiting"에서 안 붙다가 창을 움직이면 붙는다 ⓓ줌아웃하면 위젯이 전부 부풀고 떨어진다 ⓔ**위젯 크기 조절이 아예 안 된다** ⓕDock에서 앱 아이콘이 사라진다. 원인이 전부 다르다

- **추적 루프가 `requestAnimationFrame`이었다.** 데스크가 앱 창에 덮이면 macOS가 프레임을 안 주므로 루프가 멈춘다(ⓒ). → `setInterval` 32ms + `backgroundThrottling: false`
- **창 크기를 위젯 크기로 되돌려 쓰고 있었다.** 줌아웃 → 위젯이 앱 최소 크기보다 작아짐 → 앱이 거부 → 그 크기를 위젯 world 크기(`/zoom`)로 기록 → 줌아웃할수록 위젯이 커진다(ⓓ). → **줌 때문에 거부된 크기는 위젯에 안 쓴다.** 위젯 크기를 바꾸는 건 셋뿐: 사용자가 위젯을 리사이즈할 때, 사용자가 **창 모서리를 끌 때**, 앱을 열 때 한 번
- **리사이즈가 안 되던 이유는 두 개**(ⓔ). ⓐ위젯의 리사이즈 손잡이가 앱 창 밑에 깔려 마우스가 닿지 않는다 ⓑ그래서 사용자가 잡는 건 앱 창 자체의 모서리인데, 그때 "창이 움직이면 도로 앉힌다" 규칙이 되돌려버렸다. → **앱 창 모서리가 곧 위젯 리사이즈다.** 창을 끌면 위젯이 그 크기·위치를 따라간다. 단 **배치 후 1.5초** 안의 프레임 변화는 앱이 시작하며 자기 창을 복원하는 것으로 보고 3회까지 되돌린다
- **창은 위젯 사각형이 아니라 그중 캔버스에 보이는 부분에 놓는다.** "위젯이 캔버스에 온전히 들어와야 창이 붙는다"는 규칙은 위젯이 사이드바나 상단 크롬에 조금만 걸쳐도 앱이 안 오게 만들었다 — 사용자 눈에는 위젯이 멀쩡히 보이는데 안내 카드만 뜬다. 이제 겹치는 부분(최소 120×90)에 창을 놓는다. 위젯이 캔버스 밖으로 거의 다 나갔을 때만 물러난다
- **앱이 크기를 거부해도 창은 그냥 보여준다.** 거부한 크기를 최소 크기로 기억해뒀다가 위젯이 그보다 작으면 창을 감추는 방식을 넣었었는데, 한 번 거부당하면 아무리 줌·리사이즈를 해도 창이 다시 안 오는 막다른 길이 됐다(실사용 확인). 이제 앱이 자기 크기를 고집하면 **그 크기로 위젯 자리에 둔다** — 옆 위젯을 좀 덮더라도 앱이 안 보이는 것보다 낫다
- **위젯이 캔버스 밖으로 나가면 창을 화면 밖(아래)으로 크기 그대로 옮긴다**(`aside`). 카드에 **"다시 가져오기" 버튼**을 둔다 — 누르면 위젯을 캔버스 안으로 옮겨서 창이 돌아온다 원래 크기로 되돌리면 화면 한복판에 큰 창이 남고, ⌘H(hide)는 애니메이션이 있어 느리고 돌아온 창이 잠시 검게 그려진다(실사용 확인). 줌아웃하면 창이 사라지고 줌인하면 돌아온다. 헬퍼는 **파이프가 닫힐 때 모든 창을 원래 자리로 되돌린다**(부모가 죽어도 창을 화면 밖에 두지 않기 위해)
- **앱을 숨기면 화면에 알린다**(`HiddenAppsToast`). 남의 브라우저를 말없이 치우면 안 된다 — 몇 개를 숨겼는지와 Dock·⌘Tab으로 돌아온다는 것을 몇 초 보여준다
- **데스크는 앱 창 밑(레벨 −1), 대신 상관없는 앱은 숨긴다**(`hideOthers`). 두 앱의 창은 z-order를 섞을 수 없어서 "앱 창이 항상 보인다"와 "데스크가 클릭으로 맨 앞에 온다"는 동시에 안 된다. 앱 창이 항상 보이는 쪽을 택하고, 레벨 −1의 부작용(크롬·파인더 밑에도 깔려 공간이 가려짐)은 **데스크가 포커스를 받을 때 그 공간의 앱을 뺀 나머지를 숨겨서** 없앤다. 숨기기는 ⌘H와 같아서 ⌘Tab·Dock으로 바로 돌아온다. (활성화 없이 `AXRaise`로만 앱 창을 데스크 위에 올리는 방법도 시도했으나 macOS에서 동작하지 않음)
- **`setVisibleOnAllWorkspaces`에 `skipTransformProcessType: true`**(ⓕ). 이게 없으면 Electron이 프로세스를 UIElement로 바꾸고, UIElement 앱은 Dock 아이콘이 없다
- **다른 데스크탑 판정은 재시도를 다 쓴 뒤에만**(약 5초). 시작 중인 앱은 창이 window server 목록에 먼저 뜨고 접근성에는 나중에 보여서, 즉시 판정하면 **막 켠 앱마다 "다른 데스크탑에 있다"**고 잘못 말한다(Craft에서 확인)
- **다른 데스크탑·전체화면에 있는 창은 `otherSpace`로 알린다.** 앱을 activate해서 그 Space를 끌어오던 D-041 방식은 화면이 앱으로 넘어가고 데스크가 가려진다(ⓐ). activate는 앱이 아예 안 떠 있을 때만
- **단축키 `⌥Space` → `⌃⌥D`.** ⌥Space는 런처(Raycast·Alfred)와 겹치고 non-breaking space를 입력한다
- **독 아이콘을 누르면 데스크가 앞으로**(`app.on('activate')`). `browser-window-focus`와 달리 데스크를 그냥 클릭할 때는 안 온다
- **"Send … back" 버튼을 위젯 헤더로 옮겼다.** 창이 위젯 본문을 덮으므로 본문 버튼은 누를 수 없다. 하는 일은 창을 원래 크기·자리로 돌려보내고 위젯을 아이콘 상태로 되돌리는 것
- 남는 한계: 데스크를 클릭하면 앱 창이 데스크 뒤로 간다(다시 부르려면 위젯 클릭·⌃⌥D). 두 앱의 창은 z-order를 섞을 수 없으므로 이건 못 없앤다

## D-071 (2026-08-22) 데스크와 앱 창은 **두 상태**, 전환은 ⌥Space 하나뿐 (D-067·070 정리)
세 번을 z-order 토글로 접근해서 세 번 다 틀렸다. macOS 제약을 먼저 적는다 — **남의 앱 창은 내 창 안에 그릴 수도 잘라낼 수도 없고, 앱 간 z-order에 끼어들 수도 없다.** 내가 정할 수 있는 건 내 창의 레벨 하나다. 그래서 **"앱 창이 위젯 위에 보인다"와 "데스크가 앞으로 올 수 있다"는 동시에 성립하지 않는다.** D-067은 앞을 택해 데스크가 크롬 밑에 갇혔고, D-070은 클릭마다 고르게 해서 앱이 계속 튀었다. 답은 **상태를 명시적으로 만드는 것**이다

- **무대 상태**: 앱 창이 슬롯에 있고 데스크는 레벨 −1. **데스크 바닥 클릭은 아무 일도 안 한다**(D-070의 `browser-window-focus` 반응 삭제)
- **데스크 상태**: 데스크가 보통 창으로 앞에. 앱 창은 **크기 복원 없이 뒤에 그대로** 둔다 — 돌아올 때 사용자가 리사이즈를 구경하지 않아도 된다. 이때 위젯은 아이콘·이름·오늘 시간 카드를 보여준다
- **전환은 셋뿐**: ⌥Space, 위젯 클릭(그 앱을 지목), 앱 위젯을 새로 열기. 그 외 어떤 클릭도 상태를 안 바꾼다
- **데스크 상태에서는 추적 루프가 아예 안 돈다.** 창이 데스크 뒤에 있는데 팬·줌마다 따라 움직이는 건 아무도 못 보는 일이고, AX 쓰기만 낭비다. `useAppSurface`의 배치 이펙트를 `isStaged`로 막았다
- **슬롯을 놓는 것과 무대를 내려오는 것을 분리했다.** 전자만 창 크기를 복원한다(`release`). ⌥Space는 이펙트를 세션 내내 수십 번 재생성하므로, 그 정리 코드에 복원이 들어 있으면 안 된다 → `placed` ref로 나눔
- **창이 요청을 거부하면 위젯이 창에 맞춘다**(`adopt`). 최소 크기·자체 레이아웃·시작 직후 프레임 복원은 재시도로 이길 수 없다. 보이는 것과 저장된 것이 항상 같아지는 유일한 방법이다. `place` 응답에 실제 rect를 창 좌표로 실어 보낸다

## D-070 (2026-08-22) 데스크가 크롬 밑에 영영 깔리던 문제 (답은 D-072)
D-067은 앱이 앉으면 데스크를 레벨 −1에 **계속** 뒀다. 대가: **크롬을 열면 데스크가 그 아래에 영영 남는다.** 클릭도 활성화도 먹는데 화면에는 안 나온다 — 눌러도 안 올라오는 창은 고장 난 창이다

- 그때의 답(`browser-window-focus`로 활성화되면 레벨 복구)은 클릭마다 앱이 튀어서 D-071이 지웠고, **D-072가 독 클릭(`activate`)만 잡는 방식으로 되살렸다**
- 우리 번들 ID로 판정하지 않는다: dev는 `com.github.Electron`이라 패키징본과 다르다. Electron 자신의 이벤트가 정확하다
- **고아 헬퍼**: 부모가 강제 종료되면 파이프 write end가 남아 EOF가 안 와 헬퍼가 계속 산다(실측: 부모 죽은 헬퍼 1개 + 산 인스턴스 2개). 각자 접근성 권한을 쥔 채 창을 안 되돌린다 → `getppid() == 1` 감시로 자살

## D-069 (2026-08-22) 배치가 실패해도 데스크가 **바닥에 갇혀 있던** 버그 — live 집합의 수명을 맞춘다
증상: 크롬을 띄우면 Focus Desk가 안 올라오고, 미션 컨트롤에서 고르면 **엉뚱한 앱이 켜졌다**. 원인은 `live` 맵에 죽은 항목이 남는 것 하나 (같은 자물쇠의 다른 얼굴이 D-072)

- `apps:place`는 헬퍼 응답 **전에** `live.set` + 레벨 −1을 한다(따라가기·raise가 첫 프레임부터 필요해서). 실패·타임아웃 시 아무도 안 지워서 데스크가 레벨 −1에 갇혔다. 죽은 항목은 `raise`로도 나갔는데 헬퍼의 `raise`는 LaunchServices라 **실행 중이 아닌 앱을 켜버렸다** → `runningApp` 가드
- **앱 종료를 아무도 몰랐다** → `gone` 이벤트 신설. `forget()` 하나로 place 실패·detach·release·gone이 전부 같은 문을 지난다
- **위치 재적용**: 방금 켜진 앱은 우리가 옮긴 뒤 자기가 기억하던 자리로 창을 되돌린다(Things). 크기에만 있던 재시도를 위치에도 건다 — 안 그러면 그 rect가 캔버스 밖이라 위젯이 슬롯을 놓아버린다
- **피커에서 고르면 그 자리에서 열린다.** D-054가 폐기한 건 "공간에 들어가면 자동 실행"이지 명시적으로 고른 앱이 아니다

## D-068 (2026-08-22) 앱 목록은 **Spotlight 색인 + 폴더 크롤 합집합**, 최근 사용순
`/Applications`·`/System/Applications`·`~/Applications` 한 단계 크롤이 전부라 `~/Downloads/Things3.app`처럼 **폴더 밖에 둔 앱은 피커에 아예 안 떴다**. 앱을 사용자가 직접 찾아 등록시키는 건 기능이 아니라 스캔이 틀렸다는 사과다

- **두 소스 합집합.** Spotlight(`MDQuery`, `kMDItemContentType == 'com.apple.application-bundle'`)가 어디에 있든 찾고, 크롤은 색인이 꺼져도 도는 바닥으로 남긴다. 중복 시 `/Applications` 사본이 이긴다
- **필터는 소스가 아니라 결과에 건다** — ⓐ다른 `.app` 내부 사본 ⓑ`/Library/` 아래 전부 ⓒ`LSUIElement`/`LSBackgroundOnly`. ⓒ가 핵심: **창을 안 여는 앱은 위젯이 대신할 게 없다**(Magnet·Raycast를 골라도 배치가 실패했다)
- **정렬은 최근 사용순**(`kMDItemLastUsedDate`, 없으면 이름순). 100개짜리 알파벳 목록은 피커가 아니다
- **캐시 수명 60초.** 영구 캐시라 실행 중 설치한 앱이 재시작 전까지 안 보였다. 스캔은 피커를 열 때만 돈다
- **색인이 없으면 말해준다.** `apps` 이벤트의 `spotlight` 플래그(결과 0개면 false) → 상시 배너가 아니라 **검색이 비었을 때만** 안내 + 설정 열기. 켜주는 건 `sudo mdutil`이라 불가능
- 대안(기각): 수동 추가 UI, 검색 경로 설정, Spotlight 단독(색인 끈 사용자에게 빈 목록)

## D-067 (2026-08-20) 앱 창은 **위젯 자리에, 위젯 크기로** — 최대화 전용을 폐기
D-038은 실제 창이 항상 우리 창 **위에** 그려진다는 이유로 "LIVE는 위젯 최대화 상태에서만"으로 도망쳤다. 그러면 앱 하나가 화면을 꽉 채우는 앱 전환기지 공간이 아니다. 원하는 건 **작은 창 여러 개를 캔버스 위에서 그대로 쓰는 것**. 상태·수치는 [APP-SURFACE.md](APP-SURFACE.md)

- **규칙 하나로 성립한다: 위젯이 캔버스 안에 온전히 들어와 있을 때만 창을 붙인다.** 잘라낼 수 없는 창이 걸칠 일 자체를 없앤다 — 밀려나면 원래 자리로 돌려보내고, 들어오면 다시 붙인다. 여유는 부착 2px·유지 8px, **400ms 버틴 뒤** 내보낸다(사이드바 300ms 슬라이드가 창을 뺏지 않게)
- **팬은 `move`(위치만, 60ms), 줌은 `place`(카메라가 멈춘 뒤 1회, 140ms).** `AXSize` 쓰기는 앱이 레이아웃을 통째로 다시 잡게 만들어 비싸다. `place`의 `raise` 플래그도 그래서 있다 — 따라갈 때마다 앱이 튀어나오면 안 된다
- **창 모드에서 앱이 앞으로 못 나오던 진짜 원인**: `setVisibleOnAllWorkspaces(true, {visibleOnFullScreen:true})`가 macOS에서 창 레벨을 올린다. 전체화면에서만 내렸기 때문에(D-051) 창 모드만 죽어 있었다 → 항상 내린다
- **앱이 열려 있는 동안 데스크는 한 단계 아래**(`setAlwaysOnTop(true,'normal',-1)`). 두 앱의 창은 z-order를 공유하지 않아 보통 레벨이면 클릭 한 번에 앱이 전부 뒤로 간다 (→ 이 상시 −1이 D-070의 문제를 낳고 D-071에서 두 상태로 정리됨)
- **리사이즈를 한 번 삼키는 앱이 있다.** Electron 기반 앱은 이전 레이아웃 처리 중에 온 `AXSize`를 무시한다 → 2pt 이상 어긋나면 90ms 뒤 한 번 더 쓰고 최종값을 보고한다
- **창을 직접 건드리면 위젯이 따라간다.** 헬퍼가 놓인 창 프레임을 0.3초마다 재서 우리가 시킨 게 아닌 변화를 알린다 → 캔버스 안이면 위젯을 창에 맞추고, 벗어나면 슬롯을 놓아준다(창은 사용자가 둔 자리 그대로). `AXObserver`는 창마다 만들고 손으로 해제해야 해서 폴링이 더 싸다
- **한 앱은 한 창.** 헬퍼가 appKey로 원래 크기를 기억하므로 같은 앱 위젯 두 개는 동시에 못 연다

## D-062 (2026-08-20) G(정리)는 위젯 **크기까지** 화면에 맞춘다

## D-051 (2026-08-17) 전체화면에서 왕복이 죽던 이유 — 창 **레벨**
전체화면(⌃⌘F)일 때 앱이 앞으로 안 나온다는 제보. Space도 z-order도 아니고 **window level**이었다: `setSimpleFullScreen`은 메뉴바를 덮으려고 창 레벨을 `NSMainMenuWindowLevel+1`로 올리는데, 다른 앱의 일반 창은 그 위로 절대 못 온다. `raise`는 정상 수행되고 아무 일도 안 일어난 것처럼 보인다

- **앱이 앉아 있는 동안만 레벨을 내리고**, 나갈 때 되돌린다. 창은 여전히 화면을 덮으므로 보이는 변화는 없다. 전체화면을 나갈 때도 플래그를 정리해 모드보다 오래 남지 않게 한다
- 전체화면을 강제로 풀었다 켜는 방식·네이티브 전체화면 차단은 안 썼다(리사이즈 애니메이션 / 실제 문제와 무관)

## D-050 (2026-08-17) 시간 저장본이 실행마다 2배로 불어나던 버그
위젯에 `36322568020304903904390000H 53m`이 찍혔다. 시간 스토어의 `load()`가 **저장본을 메모리에 더하는** 구조인데 `<React.StrictMode>`가 dev에서 `useEffect`를 두 번 돌려 두 번째가 이미 병합된 값에 또 더했다 — **실행 1회 = 정확히 2배**

- **`load()`는 프로세스당 한 번.** `isLoaded` 가드로는 부족하다(두 호출이 await 전에 나란히 통과) → 모듈 수준 `loading` 프로미스를 공유
- 더하는 병합 자체는 유지(로드 왕복 중 째깍인 초를 잃지 않으려는 원래 이유가 옳다)
- **오염된 값은 복구 불가** → 로드 시 `sanitize`로 하루가 담을 수 없는 값(`>86400`·무한대·음수)은 **버린다**. 클램프하면 24h가 찍혀 계속 거짓말을 한다. 순수함수 + vitest로 고정

## D-049 (2026-08-17) 최대화한 위젯은 화면과 1:1 — 줌을 역보정한다
최대화한 위젯의 사각형은 `viewport / zoom`(월드)이라 카드는 화면에 고정되지만 **안쪽 CSS px는 월드 단위**라, 줌아웃하면 헤더·버튼이 같이 작아져 누를 수 없게 됐다

- `fullRect`의 크기를 **스크린 픽셀**로 주고 프레임에 `scale(1/zoom)`. 원점만 월드 좌표로 남아 제자리를 지킨다
- 화면 오버레이로 꺼내지 않은 이유는 그대로: 브라우저 위젯의 살아있는 페이지가 리페어런팅에서 죽는다(D-030)

## D-048 (2026-08-17) 창 배정 — 추측을 버리고 사용자가 고르게 한다
D-045(제목 기억)는 "첫 배치에서 고른 창"이 맞다는 가정 위에 서 있는데, 창이 여러 개면 그 첫 선택부터 틀린다. 위젯 하나 = 창 하나이므로 **어느 창인지는 사용자만 안다**

- `windows` 동사를 되살렸다(D-040에서 없앤 것). 단 창 id는 여전히 없다 — 목록도 배정도 **제목**으로 오간다. 위젯의 `Any window` 줄을 누르면 열린 창 목록에서 고른다
- **다른 데스크탑의 창은 목록에 못 올린다.** AX에 안 보이고 `CGWindowList` 제목은 화면기록 권한이 필요한데 그건 D-047에서 없앴다 → **개수만** 세어 옮겨오라고 말한다
- **배정된 창이 여기 없으면 대체하지 않는다.** 앱을 활성화해 그 Space를 꺼내보고(D-041) 안 되면 `otherSpace`로 실패. 단 숨은 창이 하나도 없으면(그냥 닫힌 제목) 조용히 기존 규칙으로 폴백
- 제목 없는 창(자체 툴킷 창)은 기억할 키가 없어 배정 불가로 표시한다

## D-047 (2026-08-17) 라이브 썸네일 폐기 — 위젯은 앱 아이콘으로
1fps 캡처(D-038 Phase B)를 통째로 지운다. 화면기록 권한, `capture` 명령, `useAppThumbnail`, Preview 버튼이 같이 사라졌다

- **400px로 줄인 창은 무엇을 하던 화면인지 못 알아본다.** 남는 건 "살아있다"는 느낌뿐인데 뒤에 있는 창은 대개 변하지도 않는다
- **얻는 것이 더 크다**: 마찰이 큰 화면기록 권한이 사라져 접근성 하나만 남고, 배포 시 권한 재승인·공증 표면도 준다
- 대신 아이콘 + 앱 이름 + **오늘 이 앱에 쌓인 시간** + 창 제목(D-045). 되살릴 일이 생기면 구현이 git 이력에 있다

## D-045 (2026-08-17) 창이 여러 개일 때 — 창 id 대신 **제목을 기억하되 갱신한다**
창 id를 두지 않기로 한 대가(D-040)가 드러나는 지점: 편집기에 프로젝트 창이 셋이면 `AXFocusedWindow`가 매번 다른 창을 집는다

- 위젯이 `windowTitle` 한 필드를 갖고 `place`에 실어 보낸다. 헬퍼 선택 순서: ① 제목 일치 → ② 포커스된 창 → ③ 가장 큰 창. **폴백이 기존 규칙이라 나빠질 수 없다**
- **첫 제목을 고정하지 않고 성공할 때마다 덮어쓴다.** 고정하면 편집기에서 폴더를 바꾸는 순간 영영 못 찾는다
- **`avoid`**: 같은 공간의 다른 위젯이 이미 기억한 제목들. 없으면 두 번째 위젯이 첫 위젯의 창에 그대로 올라탄다. 단 후보가 그것뿐이면 회피하지 않는다
- `raise`·`restore`도 헬퍼가 기억한 배치 창 제목을 쓴다. 한계: 같은 제목 두 개(`Untitled`), 제목 없는 창

## D-044 (2026-08-17) 창 크기 기억 = 원래 크기를 **잃지 않는 것**
"위젯별로 마지막 창 크기를 기억해 재현"은 성립하지 않았다(당시 LIVE는 최대화 전용이라 사각형이 하나뿐). 실제 결함은 반대쪽 — 원래 크기를 **돌려주지 못하는 경로**

- 창을 되돌리는 건 렌더러의 `release`인데 **데스크 자신이 사라질 때는 그게 안 돈다**(종료·⌘W). 원래 프레임은 헬퍼 메모리에만 있어 프로세스와 함께 사라진다 → `before-quit`에서 `restore`를 보내고 250ms 뒤 실제 종료, 창 `close`에서도 같은 복원
- 남은 구멍: 강제 종료(SIGKILL)·헬퍼 크래시. 디스크 영속화는 프로토콜과 시작 시 복원 정책이 붙어서 미채택 — 실제로 겪으면 그때

## D-043 (2026-08-17) 캔버스 월드 컨테이너의 `will-change: transform`은 움직일 때만
줌인하면 모든 위젯의 글자가 뭉개지는 문제(앱 서피스와 무관, 캔버스 전체). 월드 컨테이너에 `will-change: transform`이 상시 걸려 있어 브라우저가 그 레이어를 래스터화해두고 GPU로 확대만 하고 있었다 — 배율이 바뀌어도 다시 그리지 않으니 글자 비트맵이 늘어나 흐려짐

- `useCameraMotion`(카메라 x/y/zoom 변경 후 140ms을 "움직이는 중"으로 봄)을 추가해, 그동안만 `will-change: transform`을 걸고 멈추면 `auto`로 푼다. 멈추는 순간 새 배율로 다시 그려져 선명해짐
- 상시 승격을 안 쓰는 이유: 팬/줌 중엔 레이어 승격이 필요(리페인트 없이 GPU 합성)하지만, 정지 상태에서도 승격돼 있으면 그 대가(래스터 캐시 고정)가 그대로 남아 줌 결과물이 계속 흐려짐

## D-041 (2026-08-17) macOS Spaces — 앱을 데려오지 말고 데스크가 따라간다
전체화면 앱은 macOS가 **전용 Space**를 주고, 그 Space의 창은 **접근성 API에 안 보인다**(FL Studio·Antigravity 둘 다 `AXWindows` 0개, `CGWindowList`엔 존재). 창을 Space 사이로 옮기는 공개 API는 없다

- **"전체화면이면 거부"는 오판이었다.** FL Studio 하나를 보고 만든 규칙이 잘 되던 앱까지 죽였다. 창 크기로 Space를 추정하던 `isOnCurrentSpace`도 함께 제거. **거부가 아니라 시도가 기본이어야 한다**
- **순서**: ① AX에 창이 없고 `CGWindowList`엔 있으면 = 다른 Space → 앱을 활성화해 그 Space를 꺼낸다 ② 보이는 창이 전체화면이면 `AXFullScreen = false`로 풀어달라고 요청 ③ 일반 창이 되면 배치. 각 단계 0.5초 간격 재시도(최대 12회)
- **활성화는 `NSWorkspace.openApplication`**(LaunchServices). 헬퍼는 `.prohibited` 백그라운드 프로세스라 `activate()`가 무시된다(실측)
- **데스크가 따라간다**: 창을 옮길 방법은 없지만 우리 창을 모든 Space에 띄우는 방법은 있다 → `setVisibleOnAllWorkspaces(true, {visibleOnFullScreen:true})`, 해제 시 되돌린다
- **앱 자신의 전체화면은 `setSimpleFullScreen`.** 네이티브 전체화면은 Focus Desk도 전용 Space로 보내 어떤 외부 창도 못 들어온다

## D-040 (2026-08-17) 앱 서피스 구현에서 설계와 달라진 것들 (D-038 보강)
- **창 id를 없앴다.** `place`가 창을 직접 고른다 → id 레지스트리·재바인딩 문제가 통째로 사라짐. 대가는 창이 여러 개인 앱에서 특정 창을 못 고르는 것 → **D-048에서 `windows`를 되살렸다**(id 없이 제목만)
- **`AXMainWindow`는 못 쓴다 — 가장 큰 창을 고른다.** FL Studio 실측: `AXMainWindow` 에러(-25212), `AXMain`도 0. 자체 툴킷 창은 주 창을 보고하지 않는다
- **창이 리사이즈를 거부할 수 있다.** FL Studio 창은 `AXPosition`은 settable인데 `AXSize`는 **NO**다. 좌상단만 맞추면 1920×973 창이 흘러 **자기 타이틀바까지 화면 밖으로** 나간다(실제 발생) → ① settable 확인 ② 못 줄이는 창은 위젯 사각형 **중앙에** ③ 모든 배치를 `NSScreen.visibleFrame`에 클램프 ④ `placed`에 `resizable`을 실어 위젯이 표시
- **리사이즈는 size → position → size.** 화면 가장자리의 창은 첫 리사이즈가 그 자리 여유만큼 잘린다
- **원래 창 프레임을 첫 `place` 직전에 저장**했다가 `restore`가 복원. 재배치(창 따라가기)는 저장본을 덮어쓰지 않는다
- **배치 기준은 위젯의 실제 DOM 사각형**(`getBoundingClientRect`). 카메라를 다시 계산하지 않으므로 사이드바 슬라이드·창 리사이즈·위젯 크롬이 전부 자동 반영된다
- **`release`는 헬퍼 명령이 아니다.** 앱을 뒤로 보내는 대신 Electron이 자기를 앞으로 올린다 — 결과가 같고 앱 상태가 그대로 남는다
- **권한은 지연 요청.** `place`가 실패할 때 접근성 프롬프트가 뜬다. 앱 위젯을 안 쓰는 사용자에게는 물을 이유가 없다

## D-039 (2026-08-17) ⚠️ 체류 시간 판정을 "창 포커스"에서 "공간 소속 앱 집합"으로 (D-037 일부 뒤집음)

## D-038 (2026-08-17) 외부 앱은 "앱 서피스"로 — 배경층 고정 아이디어는 폐기
목표는 하나였다: **외부 앱(VSCode·Photoshop·FL Studio)을 Focus Desk 공간 안에서 쓴다.** 설계·단계는 [APP-SURFACE.md](APP-SURFACE.md)

- **폐기: 배경층 고정**(`kCGDesktopWindowLevel`). 그 층에서는 클릭·키보드를 제대로 못 받는다 — Übersicht·Plash가 거기 있는 이유가 "보여주기만" 해서다. 그러면 위젯이 전부 장식품이 되고, 줌/팬해도 위의 앱은 안 움직여 공간이라는 착시가 깨진다. 즉 **"Focus Desk를 외부 앱 뒤에"**가 되어 주객이 반대
- **채택: 앱 서피스.** 공간이 앱을 *소유*한다 — 전환하면 따라오고, 시간이 그 공간에 쌓인다. 대가는 구현 무게와 접근성 권한
- **macOS에 진짜 임베드는 불가능**: 다른 프로세스 창을 내 창의 자식으로 붙이는 공개 API가 없다. Windows는 `SetParent`로 되지만 자식 창은 *스케일*이 아니라 *리사이즈*라 ZUI 줌이 어차피 성립 안 함 → 윈도우에서도 같은 방식으로 간다
- **네이티브 표면은 헬퍼 바이너리 하나**(Swift, stdin/stdout JSON Lines). 네이티브 노드 애드온 기각: ABI 리빌드 부담, 크래시가 앱을 같이 죽임. 헬퍼는 죽어도 respawn이면 끝이고 이식이 파일 하나 교체다
- ~~LIVE는 위젯 최대화 상태에서만~~ → **D-067에서 폐기**, 창 여러 개를 각자 위젯 자리에서 쓴다
- 대안(기각): 웹 대체제만 쓰기(FL Studio 같은 건 대체제가 없어 반쪽), 픽셀 스트리밍 임베드(가려진 창 렌더 스로틀·입력 좌표 매핑으로 실사용 불가)

## D-037 (2026-08-17) 스페이스 체류 시간 — 매 틱 날짜별로 적립 (판정 기준은 D-039가 바꿈)

## D-034 (2026-08-17) ⚠️ 코드로 그리는 씬 — SVG·three.js 둘 다 시도 후 폐기

## D-031 (2026-08-16) 영상 전체화면은 위젯 안에 가둔다 — 게스트에 fullscreen API를 심음
- 요구: 유튜브 전체화면 버튼 → **영상만 커지고 위젯은 제자리**
- Electron의 실제 fullscreen은 전부 아니면 전무: 게스트가 fullscreen이면 **창까지 OS 전체화면**이고, 창을 되돌리면 게스트도 튕겨나온다. 둘이 묶여 있어 창 쪽만 막을 수 없다
- 그래서 게스트에 **가짜 fullscreen API를 주입**(`widgets/browserFullscreen.ts`). 게스트 뷰포트 = 위젯이므로 플레이어가 보는 "화면"이 곧 위젯이 된다
- 별칭을 **전부** 덮어야 한다. `requestFullscreen`만 덮었더니 YouTube가 대문자 S인 `webkitRequestFullScreen`을 써서 진짜 전체화면이 나갔다
- 한계: `:fullscreen` 의사클래스는 매칭되지 않는다. 더 크게는 위젯 최대화(D-030)나 앱 전체화면(⌃⌘F)

## D-030 (2026-08-16) 위젯 최대화는 "월드 rect 오버라이드", 리페어런팅 금지
- 헤더 더블클릭(또는 ⛶) → 그 위젯이 캔버스를 꽉 채움. Esc로 복귀
- 구현: `uiStore.maximizedWidgetId`(비영속) → Canvas가 화면을 덮는 월드 rect를 `fullRect`로 내려주고 WidgetFrame이 저장된 x/y/w/h 대신 그걸 쓴다
- **DOM 트리에서 위젯을 옮기지 않는 게 핵심.** 오버레이로 옮기면 리마운트 → `<webview>` 재로드 → 음악이 끊긴다
- 위젯 좌표는 안 건드리므로 복귀 시 원래 자리. 최대화 중 드래그·리사이즈 비활성

## D-029 (2026-08-16) ⭐ 브라우저 위젯을 `<webview>`로 전면 교체 (WebContentsView 방식 폐기)
`WebContentsView`는 페이지 위에 떠 있는 **네이티브 뷰**라 z-index·클리핑·CSS 트랜스폼이 통하지 않는다. ZUI 캔버스에 얹으려면 매 프레임 bounds를 손으로 동기화해야 하는데, 그 동기화는 이벤트에만 걸려 있어 **이벤트 없이 위치가 변하는 순간(사이드바 트랜지션) 그대로 어긋난다.** 앞선 결정 다섯 개가 전부 같은 뿌리의 증상을 하나씩 때운 것이었고 이 교체로 통째로 없어졌다

- `<webview>`(웹 컨텐츠가 페이지 레이아웃 안으로, `webviewTag: true`) → 위치·스케일·클리핑·스택 순서를 **브라우저가 알아서 한다**
- 삭제: `ipc/browser-views.ts`, `ipc/overlap.ts`, preload `browserView` API, 스냅샷·hibernation·bounds 동기화 전부
- 줌이 CSS 트랜스폼이라 **리플로우가 원천적으로 없다**(클리핑 방식이 싸우던 문제 자체가 사라짐)
- 유지: 세션 파티션 `persist:space-<spaceId>` → 스페이스마다 로그인이 분리된다
- 비용: Electron 문서가 `<webview>`를 "권장하지 않음"으로 표시. 그 권장은 **캔버스 안에 웹을 얹는 케이스를 상정하지 않은 것**이고, deprecated는 아니며 계속 지원된다

## D-009 (2026-08-16) package.json에서 `"type": "module"` 제거 → Electron 번들은 CJS
- `"type":"module"`이면 vite-plugin-electron이 main을 ESM으로 뽑는데 Electron이 그 번들의 `electron` named import를 해석 못 해 **실행 즉시 종료**한다. vite.config에서 형식만 덮어쓰는 건 실패했다 — `mergeConfig`가 **배열을 concat**해서 `formats`가 `['es','cjs']`가 되고 두 출력이 같은 파일명으로 서로 덮어쓴다
- 주의: VSCode 확장 셸은 `ELECTRON_RUN_AS_NODE=1`이 설정돼 있어 `npx electron`이 Node로 뜬다 → `env -u ELECTRON_RUN_AS_NODE`
