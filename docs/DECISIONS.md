## D-091 (2026-08-29) 마우스로도 줌·패닝 — 휠은 장치를 보고 갈린다
마우스만 쓰면 줌이 ⌘+휠 하나뿐이었고, 그건 아무도 찾지 못한다. 캔버스 줌은 이 앱의 기본 동작인데

- **마우스 휠 = 줌, 트랙패드 두 손가락 = 패닝.** 원하는 게 장치마다 반대다. 휠은 한 축밖에 못 굴려 패닝으로는 반쪽이고, 두 손가락은 양축을 다 굴리는 데다 핀치가 이미 줌이다
- **판정: `deltaX === 0 && wheelDeltaY % 120 === 0`.** 2026-08-29 실측 — 마우스 57개 이벤트가 전부 이 조건을 만족했고, 트랙패드는 92개 중 87개가 `deltaX ≠ 0`, 120의 배수는 3개뿐이었다. 값은 [wheelDevice.test.ts](../src/canvas/wheelDevice.test.ts)에 그대로 넣어 고정했다
- **판정은 굴림 하나에 한 번.** 200ms 이상 끊기면 다시 판정한다. 이벤트마다 판정하면 트랙패드의 그 3개가 패닝 도중에 줌으로 튄다
- **마우스 줌은 노치로 센다**(1노치 = 1.1배). 휠의 `deltaY`는 한 이벤트에 681까지 나온다 — 트랙패드용 `exp(-deltaY × 0.01)`에 넣으면 0.001배라 화면이 날아간다. ⌘+휠을 마우스로 쓰면 지금도 그렇게 튀고 있었다
- **⇧+휠은 세로 스크롤.** 마우스 사용자가 줌 말고 훑고 싶을 때
- **우클릭 드래그 = 패닝.** 마우스로 키 없이 한 손가락 패닝이 되는 유일한 길이다. 왼쪽 드래그는 밴드 선택이라(D-087) 내줄 수 없고, 그걸 ⇧ 뒤로 숨기면 여러 개 골라 다른 공간으로 보내기(D-090)가 어려워진다. 캔버스 우클릭은 비어 있었다 — 페이지 우클릭 메뉴는 webview 것이다(D-081)
- dev로 띄워 CDP로 확인: 우클릭 드래그 (-90,-48) → 위젯이 정확히 그만큼 밀림, 선택 바 안 뜸 / 같은 자리 왼쪽 드래그는 패닝 안 함

## D-090 (2026-08-29) 위젯을 다른 공간으로 — 선택 바에서, 하나로 되돌린다
탭 가져오기(LAUNCH)가 위젯 수십 개를 한 공간에 쏟아붓는다. 골라서 보내는 수단이 없으면 닫고 다시 만드는 것뿐이었다

- **선택 바가 주된 자리**(D-087). 여러 개를 한 번에 보내는 게 실제로 하는 일이다. 위젯 헤더의 버튼은 **그 위젯을 골라 같은 메뉴를 연다** — 헤더는 카메라 줌에 같이 늘어나므로 목록을 거기 띄우면 배율이 따라 붙는다. 메뉴 상태를 `uiStore`에 둔 이유가 이것
- **좌표: 대상이 가진 것들의 오른쪽에 이어 붙인다.** 저장된 좌표 그대로 놓으면 기존 위젯 위에 겹친다. 그룹 안의 상대 위치는 유지 — 그러지 않으면 정렬해둔 게 흐트러진다. 빈 공간이면 원점
- **실행 취소 하나로 전부.** `lastMoved`(from·to·widgets)를 두고 원래 좌표·z까지 되돌린다. 옮긴 뒤에는 화면에 없어서, 없으면 어디로 갔는지 찾을 방법이 없다
- **웹 위젯은 옮기면 로그아웃된다.** `persist:space-<id>` 파티션이 공간마다 다르다(D-074). 모르고 겪으면 버그로 보이므로 옮긴 직후 한 줄 알린다
- **앱 위젯은 옮길 때 창을 놓는다**(D-072) — 이 공간에 없는 슬롯에 실제 창이 앉아 있을 수 없다
- **새 공간으로 보낼 때 그 공간으로 이동하지 않는다.** `addSpace(name, false)`. 지금 공간을 정리하는 중이다
- dev로 띄워 CDP로 확인: 3개 선택 → 이동 → 원래 공간 0개 → 실행 취소로 3개 복귀(좌표 그대로) / 헤더 버튼 → 1 selected + 메뉴 / 새 공간 이름으로 이동 후에도 원래 공간에 머무름 / 브라우저 위젯 이동 시 로그인 안내 / Esc가 메뉴 → 선택 순으로 닫힘

## D-089 (2026-08-29) 앱 위젯은 기본 끔 — 창 붙이기는 설정에서
처음 보는 앱이 접근성 권한을 요구하고 다른 앱을 전부 숨기면 환불 사유가 된다. 창 붙이기는 실기 검증도 안 끝났다

- **기본**: 앱 타일 = 아이콘 + 이 공간에서 쓴 시간 + 클릭하면 실행·전환. 창을 슬롯에 앉히지 않는다. **권한이 필요 없다** — 앱 전환 감지는 `NSWorkspace.didActivateApplicationNotification`이고 프롬프트가 없다
- **설정 > 실험실 스위치**로 창 붙이기를 켠다. 켤 때 접근성 권한을 요청한다
- **숨기기 범위 결정을 이걸로 닫는다** — 켠 동안은 항상 숨김, 기본은 안 켜짐. "겹치는 앱만"은 D-072에서 이미 폐기
- 반응이 나쁘면 프로덕션 빌드에서 앱 위젯 항목 자체를 팔레트·런처에서 뺀다. 코드는 남긴다
- 계획: [LAUNCH.md](LAUNCH.md)

## D-087 (2026-08-29) 빈 캔버스를 그냥 끌면 선택 — ⇧는 더하기로
⇧+드래그로만 여러 개를 고를 수 있었다. 빈 캔버스에서 왼쪽 드래그는 아무 일도 안 했다 — 패닝은 스페이스·가운데 버튼·두 손가락 스크롤이라 왼쪽 드래그가 비어 있었다

- **그냥 드래그 = 밴드 선택.** 빈 곳을 누른 드래그만이다. 위젯 위에서 시작한 드래그는 그대로 그 위젯 이동
- **⇧+드래그 = 기존 선택에 더하기.** 위젯 위에서도 밴드를 시작할 수 있는 건 그대로(프레임이 ⇧면 이벤트를 흘려보낸다)
- **빈 곳 클릭은 크기 0짜리 밴드**라 선택이 비워진다 — 따로 처리하지 않는다
- **선택 바**: 뭔가 골라져 있는 동안 화면 아래에 뜬다. 개수 · Grid · Cascade · Duplicate · Close · 해제. 단축키(G·⌘D)를 모르는 사람이 쓸 길이다. 예전에 걷어낸 상시 바닥 바와 다르다 — 선택이 없으면 없다
- **여러 개 닫기는 실행 취소 하나로 되돌린다.** `lastRemoved`가 위젯 하나에서 목록으로 바뀌었다. 5개를 닫고 1개만 돌아오면 안 된다
- 실행 취소 토스트는 선택 바가 떠 있으면 그 위(`bottom-20`)로 올라간다
- CDP로 확인: 그냥 드래그 1개 → ⇧드래그로 2개 / 빈 곳 클릭 → 0개 / 위젯을 끌면 이동(709,503→749,543→복귀)

## D-086 (2026-08-27) 다이어그램 하나가 앱 전체를 흰 화면으로 만들었다
D-084에서 `--paper-fill`을 `color-mix()`로 쓴 순간, 다이어그램이 있는 공간을 열면 앱이 통째로 죽었다

- **원인 ⓐ 커스텀 속성은 계산값이 "쓴 그대로의 텍스트"다.** `getComputedStyle().getPropertyValue('--surface')`가 `color-mix(in srgb, #e8f2f6 9%, #101f28)` **문자열**을 돌려준다. Mermaid는 색을 직접 파싱해서 이건 못 읽고 던진다
- **원인 ⓑ 그 throw가 `useEffect` 안이라 React 트리 전체가 언마운트된다.** 위젯 하나가 아니라 앱이 흰 화면이 된다. 데이터에만 있는 조건이라(다이어그램을 만든 공간) 빈 프로필로는 재현이 안 됐다
- **고침 ⓐ 값을 칠해서 읽는다.** 숨긴 `<span>`에 `color: var(--토큰)`을 걸고 계산된 `color`를 읽으면 해석된 색이 나온다. 단 srgb에서 섞은 색은 `color(srgb r g b)` 형식이라 Mermaid가 또 거부한다 → `rgb()`로 변환해서 넘긴다
- **고침 ⓑ Mermaid 호출 전체를 `try`로 감쌌다.** 색이든 문법이든, 못 그리는 다이어그램은 **그 블록에서만** 못 그렸다고 말한다. 앱이 죽는 일은 없다
- **교훈**: 렌더러가 CSS 토큰을 JS로 읽어 외부 라이브러리에 넘길 때는 **해석된 값**을 넘겨야 한다. 토큰에 `color-mix`를 쓰는 건 CSS에선 안전하지만 JS로 읽는 순간 아니다

## D-085 (2026-08-27) 웹 페이지 뒤에 흰 바탕을 깐다
잡코리아가 투명하게 떠서 위젯 유리와 월페이퍼가 비쳤다

- **원인: `<webview>` 게스트의 기본 바탕이 투명이다.** 진짜 브라우저 창은 흰색으로 시작한다. 그래서 `html`/`body`에 배경을 직접 안 칠하고 "브라우저 기본 흰색"에 기대는 사이트는 뒤가 그대로 비친다. 잡코리아가 그렇고, **모든 사이트가 CSS 적용 전 한순간** 그렇다
- **`webContents.setBackgroundColor`는 없다**(BaseWindow·BrowserWindow·View·BrowserView에만 있다). 그래서 `<webview>` 엘리먼트가 CSS로 들고 있는다(`.web-page`). 브라우저 위젯과 웹앱 위젯 둘 다
- **웹 다크 스위치(D-084)를 따라가지 않고 항상 흰색.** 어두운 바탕을 원하는 페이지는 자기가 칠하고, 여기까지 오는 페이지는 정의상 **브라우저의 밝은 기본값을 기대하는** 것들이다. 다크를 깔면 밝은 사이트의 안 칠해진 영역이 검게 나온다
- CDP로 A/B: `.web-page` 없으면 `rgba(0,0,0,0)`, 있으면 `rgb(255,255,255)`

## D-084 (2026-08-26) 다크는 스위치 하나 — 위젯마다가 아니라
앱은 원래 대체로 어둡다(테마 6개 중 5개). 다크를 깨는 건 **종이 위젯 세 개**(노트·사진·스케치)뿐이었다

- **위젯별 토글은 기각.** 위젯 데이터의 `theme: 'LIGHT'`가 MVP 때 그걸 했던 잔해이고 이미 죽은 코드로 적혀 있다. D-033("위젯 색은 전부 테마 토큰에서")과도 어긋나고, 140px까지 좁아지는 헤더에 버튼이 하나 더 붙고, 밝은 위젯과 어두운 위젯이 한 캔버스에 섞이면 산만하다. 진짜 이유인 "이거 하나만 강조"는 색이 아니라 크기·위치로 하는 일이다
- **`--paper*` 토큰 한 벌.** `:root`가 테마를 따르고 `:root[data-paper='light']`가 흰 종이로 덮는다. `.photo-paper`와 `.memo-paper`가 같은 토큰을 읽으므로 세 위젯이 한 번에 바뀐다. 노트는 안에서 `--ink`·`--surface`까지 다시 정의해야 한다 — 표 선·흐린 라벨·Mermaid 색이 전부 거기서 나온다
- **기본값은 "테마 따라".** 어두운 테마에 흰 종이는 선택이지 기본이 아니다
- **웹페이지는 별개 스위치**(`nativeTheme.themeSource`). 게스트 안 `prefers-color-scheme`가 바뀌므로 **자체 다크 테마가 있는 사이트만** 어두워진다. 기본 켜짐. Chromium 강제 반전(`WebContentsForceDark`)은 안 쓴다 — 로고·사진이 망가지고 사이트별로 못 끈다
- **앱 설정은 공간이 아니라 사람의 것**이라 `prefsStore`(`prefs-v1`)에 따로 둔다. 공간은 분위기(테마·월페이퍼·날씨)를 갖고, 종이 밝기와 웹 다크는 앱 전체에 하나다
- 같이: **할 일을 눌러 고칠 수 있다.** 전에는 한 번 쓰면 끝이라 오타 하나에 지우고 다시 넣어야 했다. Enter 저장 / Esc 취소 / 빈 칸은 그대로 둠(지우기는 ✕)

## D-083 (2026-08-26) 마우스를 올리기만 해도 위젯이 튀던 버그
"브라우저 위젯 위에 마우스를 놓으면 갑자기 점프하고 크기가 작아진다." 가끔만 나서 오래 재현이 안 됐다

- **원인: 끝나지 않은 드래그가 남는다.** [WidgetFrame](../src/canvas/WidgetFrame.tsx)은 `pointerdown`에 제스처를 저장하고 `pointerup`에 지운다. `pointerup`을 **놓치면** 그 상태가 남고, **마우스는 제스처가 바뀌어도 `pointerId`가 늘 같아서** 다음에 그냥 올리기만 해도 `pointermove`가 조건을 통과한다 → 위젯이 커서를 따라간다. mode가 `resize`면 크기가 줄어든다
- **놓치는 조건**: 드래그 중 포인터 캡처를 잃을 때 — 브라우저 위젯 안 **페이지가 릴리즈를 가져가거나**, 버튼을 누른 채 **창이 백그라운드로 갈 때**(⌘Tab). 둘 다 가끔이라 재현이 안 됐다
- **고침: `e.buttons === 0`이면 제스처를 끝낸다.** `lostpointercapture`에서도 끝내고, 없는 캡처에 `releasePointerCapture`를 부르지 않는다
- **같은 결함이 네 군데였다** — 위젯 이동·리사이즈 / 카메라 패닝(공간 전체가 미끄러진다) / 선택 밴드 / 스케치 선. 전부 같은 가드를 넣었다
- CDP로 A/B 재현: 가드 없이는 hover만으로 (478,182)→(838,482), 가드 후에는 안 움직인다

## D-082 (2026-08-26) 도구를 꺼내는 단계 수를 줄인다 — 런처·웹앱 독·복제·새 탭 알림
맥에서 도구는 Dock 한 번이고, 여기서는 "더블클릭 → 팔레트 → 위젯 생성 → 시작 페이지 → 타일"이었다. 네 단계

## D-081 (2026-08-26) 페이지 안의 것을 캔버스로 꺼낸다
웹에서 본 이미지·글을 공간에 남길 방법이 없었다. 파일 드롭(D-078)은 Finder에서만 온다

- **링크 우클릭은 "새 탭으로 열기"부터다.** 웹뷰에 메뉴가 없다는 건 우클릭의 기본 동작이 없다는 뜻이었다. 새 탭은 `guest-open-url`로 보내 `target="_blank"`와 **같은 경로**를 탄다(D-065) — 옆에 브라우저 위젯. 주소 복사도 같이
- **우클릭 → "Send image/text to the canvas".** 게스트 `webContents`의 `context-menu`가 `srcURL`·`selectionText`를 준다. 이미지는 사진 위젯, 글은 노트 위젯으로 **그 위젯 오른쪽 옆에**(D-065와 같은 자리·같은 알림). 그 전까지 웹뷰에는 컨텍스트 메뉴가 아예 없었다 — 선택이 있으면 Copy, 입력칸이면 Paste도 같이 붙였다
- **이미지는 복사해서 가져온다**(`images:from-url`). 주소만 저장하면 페이지가 바뀌거나 로그인이 필요한 이미지일 때 빈 액자가 남는다. **그 공간의 세션으로** 받아오므로 로그인 뒤에 있는 이미지도 실제로 보던 그것이 온다
- **캔버스 드롭도 같은 규칙**을 받는다(`text/uri-list`·`text/html`·`text/plain`): 이미지면 사진, 링크면 브라우저 위젯, 나머지는 노트. 사파리·크롬 등 **앱 밖에서 끌어오는 경우**가 여기로 온다
- **드래그도 실제로 온다**(2026-08-26 사용자 확인). 게스트→임베더 전달이 안 될 것으로 봤는데 왔다. 우클릭은 대체 경로가 아니라 둘째 경로다
- **⚠️ 미검증: 컨텍스트 메뉴 자체.** 네이티브 메뉴라 CDP로 띄워볼 수 없었다. 우클릭 한 번이 필요하다

## D-080 (2026-08-26) 메모는 문서다 — 표·다이어그램은 그 안의 블록
"에디터 고도화"의 실체: 텍스트 위젯은 `<textarea>` 하나(27줄)였고, 표도 다이어그램도 놓을 데가 없었다. 표와 플로우차트를 **위젯 타입으로 따로 두는 안은 버렸다** — 별개의 물건을 나란히 놓는 일은 캔버스가 이미 하고, 사람들은 표를 "그 얘기를 적은 노트 안에" 그린다

- **Tiptap(ProseMirror).** 마크다운 소스+미리보기 안보다 크지만, `/` 명령·표 편집·붙여넣기·드래그가 전부 딸려온다. 마크다운 안은 표를 손으로 파이프 쳐야 해서 "사용성 개선"이라는 목적과 반대였다
- **저장은 HTML**(`getHTML()`). Tiptap v3에 에디터 레벨 마크다운 게터가 없다. 스키마 v5에서 **기존 평문 메모를 한 번 변환**한다(`asDocument`) — 파일 드롭·레거시 임포트도 같은 함수를 지난다. `isHtml`은 블록 태그를 요구한다: "<3"으로 시작하는 노트를 마크업으로 읽으면 그 줄이 사라진다
- **팔레트의 Table·Diagram은 미리 채워진 노트다.** 팔레트의 Music이 브라우저 프리셋인 것과 같은 방식 — 도구는 바로 꺼낼 수 있어야 하지만 그렇다고 타입이 늘 이유는 없다
- **다이어그램은 Mermaid**, 원자 노드 + React 노드뷰. 클릭하면 코드, 벗어나면 그림. 색은 `themeVariables`에 앱 토큰(`--ink`·`--surface`·`--accent`)을 넣어 테마를 따라간다. 소스는 `data-code` 속성으로 HTML에 남는다
- **노트는 종이다.** 유리 위의 문서는 한두 줄 넘어가면 읽기 힘들었다. 다만 **순백은 아니다** — 따뜻한 종이색에 위쪽으로 테마 accent를 7%만 섞어, 공간에서 오려낸 흰 사각형이 아니라 그 방의 종이가 되게 했다. 헤더 아래 안쪽 그림자로 유리 밑에 깔리게 하고, 본문은 68ch에서 끊는다(위젯을 넓히면 줄이 길어지는 게 아니라 지면이 넓어진다). `.memo-paper`는 배경만이 아니라 **`--ink`·`--surface`·`--panel-border`를 그 안에서 다시 정의한다** — 안쪽 테두리·표 선·흐린 라벨이 전부 그 토큰을 읽으므로, 어두운 테마에서 흰 종이에 흰 글씨가 되는 걸 배경색만 바꿔서는 못 막는다. Mermaid도 앱 루트가 아니라 **자기 블록**에서 색을 읽는다
- **`/` 메뉴는 넣기와 바꾸기로 나눈다.** Insert(표·다이어그램·코드·구분선) / Turn into(제목·목록·체크리스트·인용). 열 개짜리 평평한 목록은 훑어지지 않는다. 아이콘은 타일에 넣어 세로선을 만들고, 선택된 줄만 accent 타일 + ⏎. 정렬은 `items` 단계에서 하므로 화살표가 짚는 줄과 강조된 줄이 어긋나지 않는다
- **`/` 메뉴는 화면 좌표에 그린다.** 노트는 스케일된 월드 컨테이너 안이라 안에 그리면 줌아웃할수록 작아진다. 붙이는 건 **플러그인의 `mount`에 맡긴다** — 손으로 `body.appendChild`를 하면 `dismissOnOutsideClick`이 어느 요소가 팝업인지 몰라 안 걸리고, 위젯 바깥을 클릭해도 메뉴가 남는다. 캐럿이 변형된 컨테이너 안에 있으므로 `autoUpdate: { animationFrame: true }`
- **표 컨트롤은 커서가 표 안일 때만** 위젯 아래에 뜬다. 없으면 삽입한 크기에서 바꿀 방법이 없다
- 메모 기본 크기 360×400 → 420×460(3열 표가 안 읽혔다)

## D-079 (2026-08-26) 단축키는 ⇧+글자 하나로, 그리고 ⌃⌘F는 우리 것이 아니었다

## D-078 (2026-08-25) 한국어 입력에서 막히던 것들, 그리고 파일을 끌어다 놓기
실사용에서 한국어로 쓰면 세 군데가 어긋났다. 원인은 두 가지다

- **`e.key`는 입력 소스를 탄다.** 한국어 입력기가 켜져 있으면 G 키가 'g'를 보고하지 않는다 → N·G·F·⌃⌘F가 전부 안 먹었다. 캔버스 단축키와 게스트 전달(`before-input-event`)을 **`e.code`로 바꿨다**. ⌥ 조합은 원래 `code`였다(⌥G가 '©'로 와서). 대가는 Dvorak 같은 배열에서 물리 위치를 따른다는 것 — 이 앱의 단축키 수를 생각하면 받아들일 만하다. `?`는 `key === '?'`에 `code === 'Slash' && shiftKey`를 더했다
- **조합을 끝내는 Enter와 제출하는 Enter는 다른 Enter다.** 한글은 첫 Enter가 조합을 확정하고 두 번째가 제출인데, 첫 Enter에 항목을 추가하고 입력칸을 비우면 **확정된 마지막 글자가 그 뒤에 다시 들어와 남는다.** `isComposing`(+ keyCode 229)으로 거른다([ime.ts](../src/app/ime.ts)). Todo·Kanban·Links·사이드바·웹앱 폼에 적용. 브라우저 주소창은 `<form>` 제출이라 크로미움이 알아서 처리한다
- **파일 드롭**: 캔버스가 파인더에서 온 파일을 받는다. 이미지 → Photo(앱 폴더로 복사), PDF → Browser 위젯의 `file://`(크로미움 내장 뷰어, `webPreferences.plugins`), `.txt`·`.md`·`.csv`·`.json` → Memo. **그 외는 받지 않고 안내를 띄운다** — docx·key는 렌더러가 없어서 위젯을 만들면 빈 사각형이 된다. PDF는 복사하지 않고 원래 자리를 가리킨다(파일을 옮기면 끊긴다). 경로는 `webUtils.getPathForFile` — `File.path`는 Electron 32에서 없어졌다
- 웹앱 위젯 기본 높이 440 → 620. 피커에 후보가 서너 개만 보였다

## D-076 (2026-08-23) 팝업 차단과 앱 숨김 알림 — 원인은 둘 다 반환값·속성이었다
같은 버그를 세 번 틀리게 고친 뒤 실행해서 재현했다. 두 건 다 **고치던 곳이 애초에 실행되지 않는 코드**였다

- **팝업: `<webview>`에 `allowpopups`가 붙은 적이 없다.** JSX 불리언 축약(`allowpopups`)으로 썼는데 **React는 모르는 속성에 불리언이 오면 DOM에 안 쓴다**(경고만 남긴다). 속성이 없는 webview는 `window.open`에 null을 주고 **`setWindowOpenHandler`를 부르지도 않는다** — D-075에서 고친 건 전부 도달하지 않는 코드였다. `ALLOW_POPUPS`(`{ allowpopups: '' }`)를 스프레드하고 회귀 테스트를 붙였다. `@types/react`가 이 속성을 `boolean`으로 선언한 게 함정의 출처라 캐스트가 한 군데 필요하다
- **알림: `NSRunningApplication.hide()`는 숨기면서도 false를 돌려준다.** 이 맥의 모든 앱에서 측정했다(`unhide()`도 같다). `if app.hide() { hiddenApps.insert() }`였으니 집합이 늘 비었고 → 알림은 빈 목록을 받고, `unhideAll`은 되돌릴 대상이 없어 **숨은 앱이 영영 안 돌아왔다.** 이제 **요청했으면 기록한다**
- **교훈: 이 코드는 읽어서 검증이 안 된다.** 반환값·프레임워크의 속성 처리·비동기 플래그는 실행해야 보인다. 프로브(별도 Electron 앱, 별도 Swift 바이너리)로 앱 본체를 건드리지 않고 확인했다

## D-075 (2026-08-23) 브라우저를 브라우저답게 — 팝업·주소창·시작 페이지
실사용에서 다 걸렸다: 로그인하면 "팝업을 허용하세요"가 뜨고, 새 위젯은 `example.com`을 열고, 주소창은 주소만 받는다

- **팝업과 새 탭은 다른 것이고 답도 달라야 한다.** `setWindowOpenHandler`가 **전부 `deny`** 였다 → 페이지의 `window.open()`이 null을 받고, 사이트는 그걸 "팝업 차단"으로 읽는다. 구글·깃허브 로그인이 전부 여기서 막힌다
- **가르는 기준은 창 이름이다.** `disposition`으로 갈라봤다가 실패했다 — 팝업이 features 없이 열리면 평범한 탭으로 보이고, **`window.open('', name, …)`로 빈 주소에 열고 나중에 location을 넣는 경우**(구글 로그인이 이렇게 한다)에는 URL 검사가 바로 그 케이스를 막아버린다. 그래서 **링크 심(D-065)이 자기 `window.open`에 고정된 창 이름(`focusdesk-newtab`)을 붙이고**, 그 이름만 새 위젯으로 보낸다. 나머지는 전부 **진짜 창**이다. 팝업 창은 게스트의 세션을 물려받으므로 그 공간의 계정으로 로그인된다. preload도 node도 안 준다 — 남의 페이지다
- **주소창은 주소창이 하는 일을 한다**(`toAddress`, 테스트 있음). `youtube.com`은 사이트, `youtube`는 검색, `https://…`는 그대로. 예전엔 스킴만 붙여서 검색어를 치면 `https://검색어`로 갔다. 판정은 공백 없음 + 점 있는 호스트꼴 / `localhost:포트` / 맨 IP. 공개 접미사 목록은 안 쓴다 — 주소창이지 파서가 아니다
- **새 위젯은 시작 페이지를 연다**(`BrowserStartPage`). `example.com`은 아무도 읽고 싶지 않은 자리표고, 위젯을 만들 때마다 치우는 일이 된다. 대신 **저장한 웹앱 + 실제로 자주 간 사이트**를 타일로. 방문 집계는 로컬(`site-visits-v1`)이고 아무 데도 안 보낸다. **횟수 우선, 최근은 동점 처리** — 페이지 열 때마다 순서가 바뀌면 손이 기억을 못 한다
- 곁들여: 로딩 중엔 새로고침이 **정지 버튼**으로 / 로드 실패는 **빈 화면 대신 안내와 재시도**(취소 `-3`은 실패가 아니다) / 주소창 포커스 시 **전체 선택**, Esc로 원복 / 홈 버튼은 페이지를 닫고 시작 페이지로

## D-074 (2026-08-23) 공간별 로그인을 화면에 드러낸다
공간마다 쿠키가 분리된 건 브라우저 위젯을 쓴 첫날부터였다(`persist:space-<spaceId>`, 한 줄). **UI가 하나도 없었다.** 브라우저가 못 하는 몇 안 되는 일 중 하나가 아무도 모르고 되돌릴 수도 없는 기능이었고, 공간을 지워도 파티션은 디스크에 영구히 남았다

- **사이드바 🔑 → 이 공간이 로그인된 사이트 목록**(`session:summary`). 쿠키 도메인을 뒤 두 라벨로 묶어 센다(`www.figma.com`과 `figma.com`은 사람에겐 한 로그인). 계정 이름은 못 얻고 필요도 없다 — 패널의 일은 "이 공간의 로그인은 다른 공간과 별개"를 보여주고 비우는 것
- **사이트 하나씩 로그아웃**(`session:clear-site`)**과 전체 로그아웃**(`session:clear`). 전자는 쿠키를 URL로 되짚어 지운다 — secure 쿠키는 http로는 안 지워지므로 `cookie.secure`로 스킴을 맞춘다
- **파비콘 대신 글자 타일.** 로그인한 사이트 목록을 아이콘 서비스에 보내면, 세션을 갈라놨다고 말하는 바로 그 화면에서 그 목록을 밖으로 흘린다
- **공간을 지우면 파티션도 지운다**(`spaces:delete`). 없는 프로젝트의 살아 있는 로그인이 디스크에 남을 이유가 없다

## D-073 (2026-08-23) 웹앱 위젯 — 앱 위젯처럼 생겼는데 실체는 브라우저
앱 위젯(D-038)은 대가가 크다: 접근성 권한, 창 추적, 상관없는 앱 숨김. 그런데 프로젝트가 실제로 굴러가는 도구(Figma·유튜브뮤직·노션·리니어)는 **대부분 웹이다.** 저장해 둔 웹앱을 위젯으로 세운다 — 아이콘 타일, 눌러서 열기까지 앱 위젯과 똑같고 안은 `<webview>`다

- **대가가 없다.** 권한도, 창 이동도, 숨김도 없이 "공간에 도구가 서 있다"를 얻는다. 앱 위젯은 그대로 두고 그 옆에 놓는다
- **저장 목록은 공간이 아니라 사용자의 것**(`webapps-v1`, electron-store). 같은 Figma를 여러 공간에 세울 수 있고 **세션은 공간별**이라 공간마다 다른 계정이다(D-074와 짝)
- **열린 상태를 저장한다**(`open`). 앱 위젯의 열림은 저장 안 한다 — 진짜 창은 재시작을 못 넘기니까. 페이지는 넘긴다. 공간을 다시 열면 보던 페이지 그대로고, **안 연 타일은 로드도 안 하므로** 웹앱을 열 개 깔아둬도 시작이 안 무겁다
- **아이콘: 이모지는 사용자가, 이미지는 사이트가 준다**(`page-favicon-updated`). 파비콘을 아이콘 서비스에서 받아오지 않는다 — 사용자가 쓰는 사이트 목록을 그쪽에 넘기는 일이다. 사용자가 이모지를 골랐으면 파비콘이 덮어쓰지 않는다
- **주소는 따라 움직이고 홈은 안 움직인다.** `url`은 이동할 때마다 갱신(pushState 포함), `homeUrl`은 저장된 주소 — 홈 버튼이 돌아갈 자리
- **관리는 피커 안에서 끝낸다.** 목록의 연필 → 수정·삭제. 타일에서만 편집할 수 있으면 **위젯을 지운 웹앱은 이름도 못 바꾸고 지울 수도 없다**
- **기본 크기 560×440.** 브라우저 위젯(900×620)보다 작다 — 캔버스보다 큰 기본값은 가운데 정렬 때 위젯 헤더를 화면 위로 밀어내 손댈 수 없게 만든다
- 링크의 "새 탭"은 여전히 **브라우저 위젯**을 만든다(D-065). 링크가 여는 건 페이지지 저장할 도구가 아니다

## D-072 (2026-08-22) 앱 위젯 재작업 — 창 레벨 −1 폐기, 리사이즈는 창 모서리로
실사용에서 나온 문제들: ⓐ앱이 위젯 자리가 아니라 화면 가득 뜬다 ⓑ데스크로 못 돌아온다 ⓒ위젯이 "waiting"에서 안 붙다가 창을 움직이면 붙는다 ⓓ줌아웃하면 위젯이 전부 부풀고 떨어진다 ⓔ**위젯 크기 조절이 아예 안 된다** ⓕDock에서 앱 아이콘이 사라진다. 원인이 전부 다르다

- **추적 루프가 `requestAnimationFrame`이었다.** 데스크가 앱 창에 덮이면 macOS가 프레임을 안 주므로 루프가 멈춘다(ⓒ). → `setInterval` 32ms + `backgroundThrottling: false`
- **창 크기를 위젯 크기로 되돌려 쓰고 있었다.** 줌아웃 → 위젯이 앱 최소 크기보다 작아짐 → 앱이 거부 → 그 크기를 위젯 world 크기(`/zoom`)로 기록 → 줌아웃할수록 위젯이 커진다(ⓓ). → **줌 때문에 거부된 크기는 위젯에 안 쓴다.** 위젯 크기를 바꾸는 건 셋뿐: 사용자가 위젯을 리사이즈할 때, 사용자가 **창 모서리를 끌 때**, 앱을 열 때 한 번
- **리사이즈가 안 되던 이유는 두 개**(ⓔ). ⓐ위젯의 리사이즈 손잡이가 앱 창 밑에 깔려 마우스가 닿지 않는다 ⓑ그래서 사용자가 잡는 건 앱 창 자체의 모서리인데, 그때 "창이 움직이면 도로 앉힌다" 규칙이 되돌려버렸다. → **앱 창 모서리가 곧 위젯 리사이즈다.** 창을 끌면 위젯이 그 크기·위치를 따라간다. 단 **배치 후 1.5초** 안의 프레임 변화는 앱이 시작하며 자기 창을 복원하는 것으로 보고 3회까지 되돌린다
- **창은 위젯 사각형이 아니라 그중 캔버스에 보이는 부분에 놓는다.** "위젯이 캔버스에 온전히 들어와야 창이 붙는다"는 규칙은 위젯이 사이드바나 상단 크롬에 조금만 걸쳐도 앱이 안 오게 만들었다 — 사용자 눈에는 위젯이 멀쩡히 보이는데 안내 카드만 뜬다. 이제 겹치는 부분(최소 120×90)에 창을 놓는다. 위젯이 캔버스 밖으로 거의 다 나갔을 때만 물러난다
- **앱이 크기를 거부해도 창은 그냥 보여준다.** 거부한 크기를 최소 크기로 기억해뒀다가 위젯이 그보다 작으면 창을 감추는 방식을 넣었었는데, 한 번 거부당하면 아무리 줌·리사이즈를 해도 창이 다시 안 오는 막다른 길이 됐다(실사용 확인). 이제 앱이 자기 크기를 고집하면 **그 크기로 위젯 자리에 둔다** — 옆 위젯을 좀 덮더라도 앱이 안 보이는 것보다 낫다
- **위젯이 캔버스 밖으로 나가면 창을 화면 밖(아래)으로 크기 그대로 옮긴다**(`aside`). 카드에 **"다시 가져오기" 버튼**을 둔다 — 누르면 위젯을 캔버스 안으로 옮겨서 창이 돌아온다 원래 크기로 되돌리면 화면 한복판에 큰 창이 남고, ⌘H(hide)는 애니메이션이 있어 느리고 돌아온 창이 잠시 검게 그려진다(실사용 확인). 줌아웃하면 창이 사라지고 줌인하면 돌아온다. 헬퍼는 **파이프가 닫힐 때 모든 창을 원래 자리로 되돌린다**(부모가 죽어도 창을 화면 밖에 두지 않기 위해)
- **앱을 숨기면 화면에 알린다**(`HiddenAppsToast`). 남의 브라우저를 말없이 치우면 안 된다 — 몇 개를 숨겼는지와 Dock·⌘Tab으로 돌아온다는 것을 보여준다
  - **2026-08-23: 이 알림은 한 번도 뜬 적이 없었다. 원인이 네 개였다.**
  - ⓐ **`hideOthers()`를 아무도 제때 안 불렀다.** `setStaged(true)`에서 부르는데 그 시점은 헬퍼가 답하기 전이라 `landed`가 비어 즉시 return한다. 창이 실제로 앉은 뒤(`landed.add`) 다시 부르는 곳이 없어서, 실제로 숨는 건 데스크가 우연히 포커스를 받을 때뿐이었다 → **`place` 응답에서 `landed.add` 직후에 부른다**
  - ⓑ **상태가 아니라 변화를 보냈다.** 헬퍼는 이미 숨은 앱을 건너뛰고 `count > 0`일 때만 emit하는데 **되돌리는 코드가 없었다** → 첫 숨김 이후로는 숨길 게 0개라 영영 emit이 없다. 이제 **숨긴 집합 전체를 매번** 보낸다(이름순 정렬, `Set`은 순서가 없다). 헬퍼가 자기가 숨긴 것만 기억하고(`hiddenApps`), 스테이지를 내리면 `unhideAll`, 파이프가 닫혀도 `restoreAll`에서 푼다
  - ⓒ **`hide()`는 비동기다.** 고치는 과정에서 `emitHidden()`이 `isHidden == true`로 집합을 걸렀는데, `hide()`는 요청만 받고 돌아오므로 같은 런루프 턴에서는 플래그가 아직 false다 → **방금 숨긴 앱이 전부 걸러져 빈 배열이 나갔다.** 이제 필터가 없다. 집합에서 빠지는 건 폴링이 아니라 이벤트다(`didUnhideApplication`·`didTerminateApplication` 관찰)
  - ⓓ **자리와 수명.** 화면 아래 가운데(`bottom-6`)는 **이 알림이 설명하는 바로 그 상태에서 앱 창 뒤다**(데스크가 레벨 −1) → **상단 크롬(`top-7`)으로.** 앱 창은 `canvasArea().y`(84px) 아래에만 놓인다. 6초 뒤 사라지던 것도 → **숨긴 앱이 있는 동안 계속**, 아이콘을 누르면 그 앱만 복귀(`unhide`)
- **데스크는 앱 창 밑(레벨 −1), 대신 상관없는 앱은 숨긴다**(`hideOthers`). 두 앱의 창은 z-order를 섞을 수 없어서 "앱 창이 항상 보인다"와 "데스크가 클릭으로 맨 앞에 온다"는 동시에 안 된다. 앱 창이 항상 보이는 쪽을 택하고, 레벨 −1의 부작용(크롬·파인더 밑에도 깔려 공간이 가려짐)은 **데스크가 포커스를 받을 때 그 공간의 앱을 뺀 나머지를 숨겨서** 없앤다. 숨기기는 ⌘H와 같아서 ⌘Tab·Dock으로 바로 돌아온다. (활성화 없이 `AXRaise`로만 앱 창을 데스크 위에 올리는 방법도 시도했으나 macOS에서 동작하지 않음)
- **`setVisibleOnAllWorkspaces`에 `skipTransformProcessType: true`**(ⓕ). 이게 없으면 Electron이 프로세스를 UIElement로 바꾸고, UIElement 앱은 Dock 아이콘이 없다

## D-071 (2026-08-22) 데스크와 앱 창은 **두 상태**, 전환은 ⌥Space 하나뿐 (D-067·070 정리)

## D-067 (2026-08-20) 앱 창은 **위젯 자리에, 위젯 크기로** — 최대화 전용을 폐기

- **한 앱은 한 창.** 헬퍼가 appKey로 원래 크기를 기억하므로 같은 앱 위젯 두 개는 동시에 못 연다

## D-059 (2026-08-19) 위젯을 드래그해 키우면 **내용도 같이 커진다**
지금까지 리사이즈는 "같은 크기의 내용에 더 넓은 자리"였다. 사용자가 원한 건 반대 — 줌아웃해두면 위젯 글자가 손톱만 해지는데, 그때 위젯을 키워도 여백만 늘었다

- 본문을 `scale(width / defaultSize.width)`로 그린다(0.5~3배). 안쪽 박스를 `크기/배율`로 잡아 스케일 후 프레임을 정확히 채운다. 헤더는 스케일 밖이라 버튼 크기가 안 변한다
- **너비 기준**이다. 세로로만 늘리면 배율은 그대로고 내용이 더 보인다 — 폭에 맞춰 확대하는 문서 뷰어와 같은 규칙
- **브라우저 위젯은 제외**(진짜 페이지는 스스로 다시 배치한다. 두 배율이 곱해지면 흐려지기만 — 페이지 배율은 D-058이 따로 한다)

## D-058 (2026-08-19) 브라우저 위젯에 **페이지 줌** — 캔버스 줌으로는 못 하는 일
캔버스 줌은 CSS `scale()`이라 페이지가 리플로우하지 않는다(D-029). 위젯을 키우면 **뷰포트만 넓어져서** 유튜브는 여백·추천 목록만 늘고 영상은 그대로다

- `webview.setZoomFactor` + 위젯별 `data.zoom` 영속(50~300%). 주소창 −/%/+ 와 ⌘+·⌘−·⌘0
- 게스트 안의 ⌘ 조합은 앱에 안 오므로 main의 `before-input-event`가 **게스트 id와 함께** 렌더러로 넘긴다(Esc·⌃⌘F와 같은 경로)
- main에서 바로 `contents.setZoomFactor`를 부르지 않았다 — 값이 위젯 문서에 안 남아 재시작하면 사라진다

## D-055 (2026-08-18) 브라우저 위젯의 새 창 링크에 목적지를 준다 (열리는 곳은 D-065가 바꿈)

## D-054 (2026-08-18) 공간에 들어가도 앱을 자동 실행하지 않는다 (D-046 폐기)

- "무거운 앱만 빼기" 같은 예외 규칙은 안 만들었다. 무거움의 기준을 앱이 정할 수 없고, 자동 실행이 필요하다고 느끼면 그때 사용자가 켜는 스위치로 되살리는 게 낫다

## D-053 (2026-08-17) 공간 문서도 종료 직전에 동기 저장한다
- 메모를 치다 바로 ⌘Q·⌘W하면 마지막 한 줄이 사라졌다. 저장이 500ms 디바운스인데 **`beforeunload` 플러시가 공간 문서에만 빠져 있었다** — D-037이 시간 스토어에 넣은 그 처리를, 정작 사용자가 타이핑하는 문서에는 안 넣었다
- `flushSaves()`가 대기 중인 타이머를 걷어내고 **`spaces:save-sync`**(`sendSync`)로 쓴다. `invoke`는 창 파괴와 경합해 유실된다는 D-037의 근거 그대로
- 디바운스를 줄이는 방식은 안 썼다 — 매 키 입력마다 파일을 쓰게 되고 경합 자체는 그대로 남는다. 강제 종료(SIGKILL)는 여전히 못 막는다(D-044의 창 프레임과 같은 한계)
- **위젯 ✕ 삭제는 이 결정과 무관하다.** 저장 실패가 아니라 의도된 삭제이고, 보호 수단(Undo)은 별건 — STATUS "다음 할 일" 2번

## D-048 (2026-08-17) 창 배정 — 추측을 버리고 사용자가 고르게 한다
D-045(제목 기억)는 "첫 배치에서 고른 창"이 맞다는 가정 위에 서 있는데, 창이 여러 개면 그 첫 선택부터 틀린다. 위젯 하나 = 창 하나이므로 **어느 창인지는 사용자만 안다**

- `windows` 동사를 되살렸다(D-040에서 없앤 것). 단 창 id는 여전히 없다 — 목록도 배정도 **제목**으로 오간다. 위젯의 `Any window` 줄을 누르면 열린 창 목록에서 고른다
- **다른 데스크탑의 창은 목록에 못 올린다.** AX에 안 보이고 `CGWindowList` 제목은 화면기록 권한이 필요한데 그건 D-047에서 없앴다 → **개수만** 세어 옮겨오라고 말한다
- **배정된 창이 여기 없으면 대체하지 않는다.** 앱을 활성화해 그 Space를 꺼내보고(D-041) 안 되면 `otherSpace`로 실패. 단 숨은 창이 하나도 없으면(그냥 닫힌 제목) 조용히 기존 규칙으로 폴백
- 제목 없는 창(자체 툴킷 창)은 기억할 키가 없어 배정 불가로 표시한다

## D-045 (2026-08-17) 창이 여러 개일 때 — 창 id 대신 **제목을 기억하되 갱신한다**
창 id를 두지 않기로 한 대가(D-040)가 드러나는 지점: 편집기에 프로젝트 창이 셋이면 `AXFocusedWindow`가 매번 다른 창을 집는다

- 위젯이 `windowTitle` 한 필드를 갖고 `place`에 실어 보낸다. 헬퍼 선택 순서: ① 제목 일치 → ② 포커스된 창 → ③ 가장 큰 창. **폴백이 기존 규칙이라 나빠질 수 없다**
- **첫 제목을 고정하지 않고 성공할 때마다 덮어쓴다.** 고정하면 편집기에서 폴더를 바꾸는 순간 영영 못 찾는다
- **`avoid`**: 같은 공간의 다른 위젯이 이미 기억한 제목들. 없으면 두 번째 위젯이 첫 위젯의 창에 그대로 올라탄다. 단 후보가 그것뿐이면 회피하지 않는다
- `raise`·`restore`도 헬퍼가 기억한 배치 창 제목을 쓴다. 한계: 같은 제목 두 개(`Untitled`), 제목 없는 창

## D-041 (2026-08-17) macOS Spaces — 앱을 데려오지 말고 데스크가 따라간다
전체화면 앱은 macOS가 **전용 Space**를 주고, 그 Space의 창은 **접근성 API에 안 보인다**(FL Studio·Antigravity 둘 다 `AXWindows` 0개, `CGWindowList`엔 존재). 창을 Space 사이로 옮기는 공개 API는 없다

- **"전체화면이면 거부"는 오판이었다.** FL Studio 하나를 보고 만든 규칙이 잘 되던 앱까지 죽였다. 창 크기로 Space를 추정하던 `isOnCurrentSpace`도 함께 제거. **거부가 아니라 시도가 기본이어야 한다**
- **순서**: ① AX에 창이 없고 `CGWindowList`엔 있으면 = 다른 Space → 앱을 활성화해 그 Space를 꺼낸다 ② 보이는 창이 전체화면이면 `AXFullScreen = false`로 풀어달라고 요청 ③ 일반 창이 되면 배치. 각 단계 0.5초 간격 재시도(최대 12회)
- **활성화는 `NSWorkspace.openApplication`**(LaunchServices). 헬퍼는 `.prohibited` 백그라운드 프로세스라 `activate()`가 무시된다(실측)
- **데스크가 따라간다**: 창을 옮길 방법은 없지만 우리 창을 모든 Space에 띄우는 방법은 있다 → `setVisibleOnAllWorkspaces(true, {visibleOnFullScreen:true})`, 해제 시 되돌린다
- **앱 자신의 전체화면은 `setSimpleFullScreen`.** 네이티브 전체화면은 Focus Desk도 전용 Space로 보내 어떤 외부 창도 못 들어온다

## D-040 (2026-08-17) 앱 서피스 구현에서 설계와 달라진 것들 (D-038 보강)
- **창 id를 없앴다.** `place`가 창을 직접 고른다 → id 레지스트리·재바인딩 문제가 통째로 사라짐. 대가는 창이 여러 개인 앱에서 특정 창을 못 고르는 것 → **D-048에서 `windows`를 되살렸다**(id 없이 제목만)
- **`AXMainWindow`는 못 쓴다 — 가장 큰 창을 고른다.** FL Studio 실측: `AXMainWindow` 에러(-25212), `AXMain`도 0. 자체 툴킷 창은 주 창을 보고하지 않는다
- **창이 리사이즈를 거부할 수 있다.** FL Studio 창은 `AXPosition`은 settable인데 `AXSize`는 **NO**다. 좌상단만 맞추면 1920×973 창이 흘러 **자기 타이틀바까지 화면 밖으로** 나간다(실제 발생) → ① settable 확인 ② 못 줄이는 창은 위젯 사각형 **중앙에** ③ 모든 배치를 `NSScreen.visibleFrame`에 클램프 ④ `placed`에 `resizable`을 실어 위젯이 표시
- **리사이즈는 size → position → size.** 화면 가장자리의 창은 첫 리사이즈가 그 자리 여유만큼 잘린다
- **원래 창 프레임을 첫 `place` 직전에 저장**했다가 `restore`가 복원. 재배치(창 따라가기)는 저장본을 덮어쓰지 않는다
- **배치 기준은 위젯의 실제 DOM 사각형**(`getBoundingClientRect`). 카메라를 다시 계산하지 않으므로 사이드바 슬라이드·창 리사이즈·위젯 크롬이 전부 자동 반영된다
- **`release`는 헬퍼 명령이 아니다.** 앱을 뒤로 보내는 대신 Electron이 자기를 앞으로 올린다 — 결과가 같고 앱 상태가 그대로 남는다
- **권한은 지연 요청.** `place`가 실패할 때 접근성 프롬프트가 뜬다. 앱 위젯을 안 쓰는 사용자에게는 물을 이유가 없다

## D-038 (2026-08-17) 외부 앱은 "앱 서피스"로 — 배경층 고정 아이디어는 폐기
목표는 하나였다: **외부 앱(VSCode·Photoshop·FL Studio)을 Focus Desk 공간 안에서 쓴다.** 설계·단계는 [APP-SURFACE.md](APP-SURFACE.md)

- **macOS에 진짜 임베드는 불가능**: 다른 프로세스 창을 내 창의 자식으로 붙이는 공개 API가 없다. Windows는 `SetParent`로 되지만 자식 창은 *스케일*이 아니라 *리사이즈*라 ZUI 줌이 어차피 성립 안 함 → 윈도우에서도 같은 방식으로 간다
- **네이티브 표면은 헬퍼 바이너리 하나**(Swift, stdin/stdout JSON Lines). 네이티브 노드 애드온 기각: ABI 리빌드 부담, 크래시가 앱을 같이 죽임. 헬퍼는 죽어도 respawn이면 끝이고 이식이 파일 하나 교체다
- ~~LIVE는 위젯 최대화 상태에서만~~ → **D-067에서 폐기**, 창 여러 개를 각자 위젯 자리에서 쓴다
- 대안(기각): 웹 대체제만 쓰기(FL Studio 같은 건 대체제가 없어 반쪽), 픽셀 스트리밍 임베드(가려진 창 렌더 스로틀·입력 좌표 매핑으로 실사용 불가)

## D-037 (2026-08-17) 스페이스 체류 시간 — 매 틱 날짜별로 적립 (판정 기준은 D-039가 바꿈)

- 활성 판정은 문서 포커스가 아니라 **창 포커스**로 잡았다 — 브라우저 위젯을 클릭하면 `document.hasFocus()`가 false가 된다. **그 기준은 D-039에서 다시 뒤집혔다**(공간 소속 앱 집합)
- 슬립·화면잠금은 `powerMonitor`로 away. 이중 방어로 틱 간격이 `MAX_TICK_MS`(5초)를 넘으면 초과분을 버린다
- 저장은 10초마다 + 비활성 시 즉시. 종료 직전 마지막 저장은 `beforeunload`의 **동기 IPC** — `invoke`는 창 파괴와 경합해 유실된다
- 안 넣은 것: 유휴 감지. 입력이 없어도 앱을 보고 있는 경우(영상·음악)가 핵심 용도라 오히려 과소 계산이 된다

## D-032 (2026-08-16) 상단 셸이 위젯을 먹던 문제 — 원인은 타이틀바 드래그 영역
- **범인**: `App.tsx`의 `fixed top-0 h-6 z-[60]` 드래그 영역이 **화면 최상단 24px의 모든 클릭을 삼켰다** — 위젯 헤더 버튼이 정확히 그 자리 → 트래픽 라이트 쪽(좌측 256px)만 남김
- **최대화 위젯이 상단 셸과 겹침**(사이드바 토글·Start focus·앰비언스가 y 36~76) → 최대화 rect를 상단 84px 아래로 내림
- **탈출 불가**: 웹 페이지에 포커스가 있으면 Esc·⌃⌘F가 앱에 도달하지 않는다 → main이 webview의 `before-input-event`를 받아 렌더러로 전달
- 헤더 32px/아이콘 12px → 40px/14px/히트영역 28px

## D-031 (2026-08-16) 영상 전체화면은 위젯 안에 가둔다 — 게스트에 fullscreen API를 심음
- 요구: 유튜브 전체화면 버튼 → **영상만 커지고 위젯은 제자리**
- Electron의 실제 fullscreen은 전부 아니면 전무: 게스트가 fullscreen이면 **창까지 OS 전체화면**이고, 창을 되돌리면 게스트도 튕겨나온다. 둘이 묶여 있어 창 쪽만 막을 수 없다
- 그래서 게스트에 **가짜 fullscreen API를 주입**(`widgets/browserFullscreen.ts`). 게스트 뷰포트 = 위젯이므로 플레이어가 보는 "화면"이 곧 위젯이 된다
- 별칭을 **전부** 덮어야 한다. `requestFullscreen`만 덮었더니 YouTube가 대문자 S인 `webkitRequestFullScreen`을 써서 진짜 전체화면이 나갔다
- 한계: `:fullscreen` 의사클래스는 매칭되지 않는다. 더 크게는 위젯 최대화(D-030)나 앱 전체화면(⌃⌘F)

## D-030 (2026-08-16) 위젯 최대화는 "월드 rect 오버라이드", 리페어런팅 금지
- 헤더 더블클릭(또는 ⛶) → 그 위젯이 캔버스를 꽉 채움. Esc로 복귀
- 구현: `uiStore.maximizedWidgetId`(비영속) → Canvas가 화면을 덮는 월드 rect를 `fullRect`로 내려주고 WidgetFrame이 저장된 x/y/w/h 대신 그걸 쓴다
- **DOM 트리에서 위젯을 옮기지 않는 게 핵심.** 오버레이로 옮기면 리마운트 → `<webview>` 재로드 → 음악이 끊긴다
- 위젯 좌표는 안 건드리므로 복귀 시 원래 자리. 최대화 중 드래그·리사이즈 비활성

## D-029 (2026-08-16) ⭐ 브라우저 위젯을 `<webview>`로 전면 교체 (WebContentsView 방식 폐기)
`WebContentsView`는 페이지 위에 떠 있는 **네이티브 뷰**라 z-index·클리핑·CSS 트랜스폼이 통하지 않는다. ZUI 캔버스에 얹으려면 매 프레임 bounds를 손으로 동기화해야 하는데, 그 동기화는 이벤트에만 걸려 있어 **이벤트 없이 위치가 변하는 순간(사이드바 트랜지션) 그대로 어긋난다.** 앞선 결정 다섯 개가 전부 같은 뿌리의 증상을 하나씩 때운 것이었고 이 교체로 통째로 없어졌다

- `<webview>`(웹 컨텐츠가 페이지 레이아웃 안으로, `webviewTag: true`) → 위치·스케일·클리핑·스택 순서를 **브라우저가 알아서 한다**
- 삭제: `ipc/browser-views.ts`, `ipc/overlap.ts`, preload `browserView` API, 스냅샷·hibernation·bounds 동기화 전부
- 줌이 CSS 트랜스폼이라 **리플로우가 원천적으로 없다**(클리핑 방식이 싸우던 문제 자체가 사라짐)
- 유지: 세션 파티션 `persist:space-<spaceId>` → 스페이스마다 로그인이 분리된다
- 비용: Electron 문서가 `<webview>`를 "권장하지 않음"으로 표시. 그 권장은 **캔버스 안에 웹을 얹는 케이스를 상정하지 않은 것**이고, deprecated는 아니며 계속 지원된다

## D-009 (2026-08-16) package.json에서 `"type": "module"` 제거 → Electron 번들은 CJS
- `"type":"module"`이면 vite-plugin-electron이 main을 ESM으로 뽑는데 Electron이 그 번들의 `electron` named import를 해석 못 해 **실행 즉시 종료**한다. vite.config에서 형식만 덮어쓰는 건 실패했다 — `mergeConfig`가 **배열을 concat**해서 `formats`가 `['es','cjs']`가 되고 두 출력이 같은 파일명으로 서로 덮어쓴다
- 주의: VSCode 확장 셸은 `ELECTRON_RUN_AS_NODE=1`이 설정돼 있어 `npx electron`이 Node로 뜬다 → `env -u ELECTRON_RUN_AS_NODE`
