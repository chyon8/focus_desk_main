# LAUNCH — 출시 결정과 온보딩 설계

> 2026-08-29 작성. 기능 개발이 끝나고 출시를 준비하는 단계의 결정을 모은다.
> 기술 결정 원문은 [DECISIONS.md](DECISIONS.md) D-088·089. 이 문서는 계획과 이유.

## 0. 착수 순서 — "착수해" 하면 여기 1번부터

작은 것 넷을 먼저 끝내 출시 요건을 채우고, 가장 큰 온보딩을 마지막에 붙인다. 1번은 5번의 전제다 — 탭 40개를 가져왔는데 헤더가 전부 "Browser"면 임포트 결과가 못 알아볼 화면이 된다.

| # | 할 일 | 크기 | 끝났다고 보는 기준 |
|---|---|---|---|
| 1 | ✅ 브라우저 위젯 헤더에 페이지 제목·파비콘 (D-092) | 작음 | 유튜브를 열면 헤더에 영상 제목과 유튜브 파비콘 |
| 2 | 데이터 백업 | 중간 | 폴더 열기 / 스냅샷 5개 / 내보내기·가져오기 왕복 |
| 3 | 앱 위젯 기본 끔 | 작음 | 새 프로필 첫 실행에 접근성 프롬프트 없음 |
| 4 | 세션 패널 필터 | 작음 | `doubleclick.net` 안 뜸, `naver.co.kr` 안 뭉개짐 |
| 5 | 온보딩 | 큼 | 임포트 / 웹앱 고르기 / 건너뛰기 세 갈래가 다 끝까지 감 |
| 6 | 서명·공증 | — | **사용자만 가능** (Apple Developer 인증서) |

### 1. 브라우저 위젯 헤더 — 무슨 사이트인지 보이게 ✅ 2026-08-29 (D-092)
지금 헤더는 `WIDGET_REGISTRY`의 고정 라벨 "Browser" + 고정 지구본이다. 브라우저 위젯을 여러 개 열면 전부 똑같아서 구분이 안 된다.

- **제목**: `<webview>`의 `page-title-updated`. 유튜브면 영상 제목이 그대로 온다
- **파비콘**: `page-favicon-updated`. 웹앱 위젯이 이미 쓰는 경로다 ([WebAppWidget.tsx](../src/widgets/WebAppWidget.tsx)) — ~~`images:from-url`로 그 공간 파티션에서 받아 저장한다~~ 웹앱 위젯이 실제로 하는 대로 **주소를 그대로 저장**했다 (D-092)
- **위젯 데이터에 저장한다.** 닫았다 열 때 로드를 기다리지 않고 바로 보인다. 웹앱 위젯의 `icon` 저장과 같은 패턴
- **헤더는 140px까지 좁아진다.** 자르고 `title` 속성으로 전체를 툴팁에
- **없을 때 순서**: 페이지 제목 → 도메인 → "Browser"
- 건드릴 곳: [BrowserWidget.tsx](../src/widgets/BrowserWidget.tsx)(이벤트 → 데이터), [WidgetFrame.tsx](../src/canvas/WidgetFrame.tsx)(헤더가 `widget.data`를 보게)
- 검증: 유튜브·노션·잡코리아를 각각 열어 제목·파비콘 / 앱 재시작 후에도 남아 있는지 / 로드 실패 페이지

### 2. 데이터 백업 — 로컬 온리의 대가 (D-088)
- 설정에 **데이터 폴더 열기** (`shell.openPath(app.getPath('userData'))`)
- **하루 1회 자동 스냅샷, 최근 5개.** `userData/backups/<날짜>/`에 `spaces/`와 `prefs`를 복사. 앱 시작 때 마지막 스냅샷 날짜를 보고 필요하면 뜬다
- **내보내기·가져오기** — 폴더 하나(zip 아님, 단순하게). 가져오기는 **덮어쓰지 않고 합친다**(같은 id면 건너뛴다). 맥을 바꿀 때 쓰는 길
- 검증: 스냅샷 파일이 실제로 생기는가 / 내보낸 걸 빈 프로필에 가져와 공간이 그대로 서는가

### 3. 앱 위젯 기본 끔 (D-089)
- 앱 타일 기본 동작 = 아이콘 + 이 공간에서 쓴 시간 + 클릭하면 실행·전환. 창을 슬롯에 앉히지 않는다
- 설정에 "앱 창을 공간 안에 붙이기" 스위치. **켤 때만** 접근성 권한을 요청한다
- 설정을 어디에 둘지 결정 필요 — 지금 사용자 설정은 [ThemePicker.tsx](../src/app/ThemePicker.tsx) 안에 있는데(종이·웹 다크) 거기는 외양 설정이다. 별도 설정 패널을 만들지 사이드바에 붙일지 그때 정한다
- 검증: 빈 프로필로 첫 실행 → 접근성 프롬프트가 안 뜨는가 / 스위치를 켜면 뜨는가

### 4. 세션 패널 필터 (STATUS 2번)
- `session:summary`에 로그인 쿠키만 세는 필터(`httpOnly` + 장기 만료)
- `siteOf()`를 2단계 국가 도메인까지 (`naver.co.kr`이 `co.kr`로 뭉개진다)
- 검증: 광고 도메인이 사라지고 실제 로그인한 사이트만 남는가

### 5. 온보딩
아래 3장이 설계 전부다. 순서는 ① 탭 가져오기(또는 웹앱 고르기) → ② 배경·소리 → ③ 줌아웃 → ④ 질문 하나.

**시작 전에 확인할 것 하나**: 브라우저 위젯이 **로드하지 않은 상태로 깔릴 수 있는지**. 안 되면 탭 12개만 가져와도 12개가 동시에 로드된다. 안 되면 그걸 먼저 만든다

### 6. 서명·공증 (D-027)
Developer ID 인증서 → 공증 → 자동 업데이트. **AI가 못 한다** — 사용자가 Apple Developer 계정으로 진행한다

## 1. 확정 — 로그인 없음, 데이터는 로컬

계정·서버 없이 출시한다. 지금 구조를 그대로 쓴다 (`electron-store` + `userData/spaces/*.json`).

- 첫 실행에 가입 화면이 있으면 이탈한다. "받자마자 내 공간"이 첫인상이어야 한다
- 저장하는 게 웹 세션 쿠키·화면 배치·시간 기록이다. 서버로 올리면 보안·개인정보 책임이 생기는데 그만한 값은 아직 없다
- 동기화를 요구한 사람이 없다. 맥 한 대가 기본 사용 환경이다

**출시 전 필수 (백업 없이 내보내면 안 된다):**
- [ ] 설정에 "데이터 폴더 열기"
- [ ] 하루 1회 자동 스냅샷, 최근 5개 보관
- [ ] 내보내기·가져오기 (맥을 바꿀 때 폴더 하나로)

**유료화한다면** 로그인 대신 라이선스 키(Lemon Squeezy / Paddle). 결제 → 메일로 키 → 앱에 붙여넣기. 서버 없이 되는 가장 짧은 길.

**나중에 계정을 붙일 수 있게** 공간 파일의 `id`·`updatedAt`은 유지한다.

## 2. 확정 — 앱 위젯은 기본 끔, 설정에서 켠다

두 단계로 나눈다.

- **기본**: 앱 타일 = 아이콘 + 이 공간에서 쓴 시간 + 클릭하면 실행·전환. 창을 슬롯에 앉히지 않고 다른 앱도 숨기지 않는다. 권한이 필요 없다 — 앱 전환 감지는 `NSWorkspace` 알림이고 프롬프트가 없다 ([FocusDeskHelper.swift:874](../electron/helper/macos/FocusDeskHelper.swift#L874))
- **설정 > 실험실**: "앱 창을 공간 안에 붙이기". 켤 때만 접근성 권한을 요청한다. 켠 동안은 지금처럼 **항상 숨김** — STATUS의 "숨기기 범위" 결정은 이걸로 닫힌다

처음 보는 앱이 접근성 권한을 요구하고 다른 앱을 전부 숨기면 환불 사유가 된다. 게다가 창 붙이기는 실기 검증이 안 끝났다.

**이것도 마음에 안 들면 앱 위젯 자체를 프로덕션 빌드에서 숨긴다.** 팔레트·런처에서 항목만 빼면 되고 코드는 남긴다.

## 3. 온보딩

### 원칙
1. **빈 캔버스로 시작하지 않는다.** 이 앱은 아무것도 없을 때 가장 매력이 없다
2. **첫 화면부터 사용자 자기 데이터를 쓴다.** 샘플 워크스페이스는 남의 물건이라 애착이 안 생긴다
3. **연습시키지 않는다.** 줌·드래그·정렬은 필요한 순간에 한 줄씩

### 흐름

**① 크롬 탭 가져오기 — 가장 빠른 길이지 유일한 길은 아니다**

첫 화면. 열려 있는 크롬 창과 탭을 읽어서 목록으로 보여주고, 창 단위로 고르게 한다.

```
Chrome에 창 3개, 탭 41개가 열려 있습니다.

☑ 창 1 — 12개 탭   [Figma, Notion, 클라이언트 A 브리프, ...]
☑ 창 2 — 8개 탭    [Gmail, 캘린더, ...]
☐ 창 3 — 21개 탭   [유튜브, 뉴스, ...]

Your tabs will stay in Chrome. Nothing is closed.
```

- **"Your tabs will stay" 는 첫 화면에 반드시 있어야 한다.** 브라우저 탭을 잃는 건 실제 공포다. 읽기만 하므로 사실이기도 하다
- **창 하나 = 공간 하나로 만든다.** 창을 여러 개 벌려 쓰는 사람은 이미 창으로 프로젝트를 나누고 있다. 그 구조를 그대로 옮기면 "공간이 뭔지"를 설명할 필요가 없어진다. 공간 이름은 그 창에서 가장 많이 나온 도메인으로 제안하고 고칠 수 있게
- 가져오면 위젯을 **그리드로 자동 정렬**한다 (`arrangeWidgets('grid')`가 이미 있다)

**①-b 안 가져오는 사람 — 같은 화면에 나란히 둔다**

온보딩의 목적은 탭 임포트가 아니라 **3분 안에 내 것으로 채워진 화면**이다. 임포트는 그중 가장 빠른 경로일 뿐이다. 세 갈래를 두되, **건너뛰기 링크로 숨기지 않고 같은 화면에 버튼 두 개로 나란히 둔다.** 권한 프롬프트를 피하고 싶은 사람에게 도망갈 곳이 보여야 한다.

```
[ Import from Chrome ]     [ Pick your tools instead ]
```

| 상황 | 보여줄 것 | 사용자 노동 |
|---|---|---|
| 크롬에 탭이 있고 가져온다 | ① 창·탭 목록 | 0 |
| 크롬이 없다 / 안 켜져 있다 / 가져오기 싫다 | **자주 쓰는 웹앱 고르기** | 탭 3~6번 |
| 둘 다 싫다 | 공간 1개 + 씨앗 위젯(노트·할 일) → ④로 | 0 |

- **웹앱 고르기가 기본 대안이다.** 프리셋 34개가 이미 있다(D-073). 로고를 그리드로 깔고 3~6개 고르면 그게 위젯이 된다. 크롬도 권한도 필요 없고, 결과 화면은 임포트와 거의 같다
- **크롬이 안 켜져 있으면 실패를 알리지 않는다.** "Chrome이 안 켜져 있어요" 대신 그냥 웹앱 고르기를 기본 화면으로 띄운다. 임포트 버튼은 남겨둔다
- **탭이 몇 개 없는 사람** — 임포트 결과가 4개 미만이면 웹앱 고르기를 이어서 보여준다. 허전한 화면으로 끝나면 안 된다
- **권한을 거부하면 재프롬프트가 안 된다**(macOS TCC). 시스템 설정 열기 버튼을 주고, 웹앱 고르기로 자동 이동
- **나중에 할 수 있어야 한다.** 런처(K)와 사이드바에 "Import from Chrome" 상시 항목. 온보딩에서 거절한 사람이 며칠 뒤에 하는 경로가 없으면 그 사람은 영영 안 한다


**② 배경과 소리 — 가져오는 동안 이미 깔려 있다**

임포트가 끝난 화면이 첫인상이다. 그 화면이 좋아야 한다.
- 배경은 8장 중 가장 좋은 것 하나를 기본으로 고정 (고르게 하지 않는다. 아직 취향을 물을 타이밍이 아니다)
- 로파이·재즈 앰비언스를 **자동 재생**. 볼륨은 낮게, 끄는 버튼은 눈에 보이게
- 배경 바꾸기는 온보딩이 끝난 뒤에 안내

**③ 줌아웃 한 번**

임포트한 위젯이 화면 밖까지 깔려 있으니 줌아웃은 자연히 하게 된다. 한 줄만: `⌘-`. 모든 공간이 한 화면에 펼쳐지는 장면이 제품 전체를 설명한다.

**④ 마지막 — 질문 하나와 행동 하나**

```
What are you working on today?
[ 클라이언트 A 리브랜딩 ]  → 이 이름으로 새 공간이 생긴다
```

질문은 **하나만**. 여러 개 물으면 폼이 된다. 답은 반드시 공간 이름이 되어야 한다 — 답하고 아무 일도 안 일어나면 질문을 위한 질문이 된다.

### 사용자 안에서 어떤 감정을 만드는가
- **안도** — 41개 탭이 3초 만에 정리됐고 크롬은 그대로다 (①)
- **소유** — 화면에 있는 게 전부 내 것이다. 샘플이 하나도 없다 (①)
- **놀람** — 줌아웃했더니 프로젝트가 다 보인다 (③)
- **의도** — 오늘 뭘 할지 내가 말했고 공간이 생겼다 (④)

별도의 "놀라운 것"을 따로 만들 필요는 없다. 억지 서프라이즈는 온보딩에서 역효과가 크고, ①과 ③이 이미 놀람이다.

### 하지 않을 것
- 순차 클릭 튜토리얼 오버레이, 단축키 표, 위젯 종류 나열
- 텍스트로 쓴 서사 — 읽지 않는다. 서사는 자기 탭이 정리되는 과정 그 자체다. 화면당 문장 3개 이하
- 통계·포커스 세션 — 1일차엔 빈 그래프만 보인다
- 앱 위젯·접근성 권한 (2번 결정)
- **온보딩 직후 피드백 요청** — 겪은 게 없어서 쓸 말이 없다. 피드백은 3회차 실행 또는 3일차에

### 2회차 실행이 진짜 훅
컨텍스트가 복원되는 건 두 번째 열 때 겪는다.
- 온보딩 마지막에 예고: "내일 열면 이 화면 그대로예요"
- 2회차 실행에 한 줄: "어제 이 공간에서 2시간 34분"

## 4. 위젯을 다른 공간으로 옮기기 ✅ 2026-08-29 (D-090)

임포트가 끝나면 위젯 40개가 한 공간에 있다. **거기서 골라 다른 공간으로 보내는 게 정리의 전부다.** 만들었다 — 아래가 그 설계이고, 결정 기록은 [DECISIONS.md](DECISIONS.md) D-090.

- **어디에 붙나** ⓐ**선택 바**(D-087) — 여러 개를 한 번에 보내는 게 핵심 시나리오다 ⓑ위젯 헤더 hover 메뉴(복제 옆) ⓒ⌘⇧M 정도
- **UI**: "Move to space →" + 공간 목록 + "새 공간으로". 새 공간이면 이름을 묻고 만들면서 옮긴다
- **대상 좌표**: 원래 좌표를 그대로 쓰면 기존 위젯과 겹친다. 대상 공간 위젯들의 바운딩 박스 오른쪽에 이어 붙이고, 여러 개면 **서로의 상대 위치는 유지**한다. `z`는 대상의 `topZ` 위로
- **실행 취소 필수.** 잘못 보내면 어느 공간으로 갔는지 찾기 어렵다. `lastRemoved`(spaceId + widgets) 패턴을 그대로 쓸 수 있다
- **주의 — 브라우저·웹앱 위젯은 세션이 공간별로 갈린다**(D-074). 옮기면 로그인이 달라진다. 옮긴 뒤 토스트로 한 줄 알려야 한다. 모르고 겪으면 버그로 보인다

## 5. 탭 가져오기 — 구현 메모

- **AppleScript로 읽는다.** `tell application "Google Chrome" to get {URL, title} of tabs of windows`. 창→탭 구조가 그대로 나온다. 읽기만 하므로 크롬은 안 바뀐다
- **권한 프롬프트가 "제어"라고 뜬다** — "FocusDesk가 Google Chrome을 제어하도록 허용". 이걸 그냥 만나면 무섭다. **프롬프트 전에 우리가 먼저 설명한다**: "탭 목록만 읽습니다. 크롬은 그대로 둡니다"
- **탭 수 상한이 필요하다.** 탭 100개를 전부 브라우저 위젯으로 열면 100개가 동시에 로드된다. ⓐ 창당 상한(12개쯤) ⓑ 나머지는 북마크 위젯 하나로 ⓒ **처음엔 로드하지 않은 카드**(제목+파비콘)로 깔고 클릭할 때 로드. ⓒ가 BrowserWidget에 있는지 먼저 확인할 것
- **크롬이 없거나 안 켜져 있을 때 경로가 반드시 있어야 한다.** 건너뛰기 → ④로
- 출시는 **크롬만**. Safari·Arc·Edge는 반응 보고
