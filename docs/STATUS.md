## 다음 할 일
1. **위젯 내용 줌**(2026-08-19 사용자 요청) — 캔버스 줌은 CSS `scale()`이라 페이지가 리플로우하지 않는다. 브라우저 위젯에 페이지 줌(`webview.setZoomFactor` + `data.zoom` 영속, 주소창 −/%/+ 와 ⌘+/⌘−/⌘0)을 넣고, 게스트 안에서 누른 키는 main의 `before-input-event`가 **게스트 webContents id와 함께** 렌더러로 넘긴다(Esc·⌃⌘F와 같은 경로)
2. **캔버스 밀도** — 배치(열 수)를 건드리는 방법은 다 해봤고 더 나올 게 없다. 남은 건 **ⓐ "한눈에 보기"**(정리할 때 위젯 **크기까지** 격자에 맞춰 여백을 없앰, 원래 크기 기억) ⓑ헤더 줌 역보정 ⓒ줌 0.6 미만 LOD — [ARCHITECTURE.md](ARCHITECTURE.md) "캔버스 밀도·가독성". **ⓐ가 사용자가 말한 "꽉 차게"에 실제로 답하는 유일한 안**
3. **위젯 삭제 보호**(미착수, 사용자 확정 대기) — 지금 위젯 ✕는 확인·되돌리기 없는 영구 삭제([WidgetFrame.tsx](../src/canvas/WidgetFrame.tsx)), 사이드바 공간 삭제는 JSON 파일+누적 시간까지 즉시 삭제([Sidebar.tsx](../src/app/Sidebar.tsx)). **추천: 위젯은 Undo 토스트(8초), 공간은 확인 다이얼로그.** 다이얼로그를 위젯에 안 쓰는 이유는 매번 뜨면 "예" 반사가 생겨 실제로 안 막히기 때문
4. **로컬 빌드로 실사용**(D-044~055) — `npm run dist`로 빌드해 며칠 쓰면서 창 배정·시간 값·전체화면 왕복 실기 확인. **패키징본은 접근성 권한을 새로 줘야 함**(바이너리 경로 기준)
5. **사용성 QA** — UX가 최선인지, 실사용 오류 없는지 훑는 라운드 (3번 검증 후)
6. **배포 마무리**(D-027) — Developer ID 인증서 → 공증 + 자동 업데이트. 헬퍼 바이너리도 서명 대상
7. 미검증: ⌥Space 왕복(위젯 클릭 왕복은 확인됨), 60fps 실측, 앰비언스 소리 품질 / 정리: `legacy/` 삭제 / Reader 위젯 보류(D-028)

## 정리 대기 (급하지 않음, 발견 시 같이 처리)
- dev 실행 시 `unset ELECTRON_RUN_AS_NODE` 필요(VSCode 확장 환경이 넣는 변수, 그대로면 Electron이 node 모드로 떠서 죽음). 사용자 터미널에선 무관
- **유튜브 진짜 전체화면**(순위 내림, 2026-08-17). `webview`의 `enter-html-full-screen`/`leave-html-full-screen`을 받아 위젯 최대화 + 앱 전체화면을 자동으로 같이 걸고 같이 풀기(버튼 추가 없음, `browserFullscreen.ts` 같이 정리)
- 체류 시간: 디스플레이만 꺼진 상태(시스템 슬립·잠금 아님)는 계속 카운트됨. 유휴 감지는 의도적으로 안 넣음(D-037)
- **웹 로그인이 한 번 풀렸다가 돌아옴**(2026-08-18, 사용자 확인). 앱 코드엔 세션·쿠키를 지우는 곳이 없고 파티션·쿠키 DB도 그대로였다. 원인 미확정, 재현되면 그때 판다 — 유력 후보는 쿠키 값 암호화 키(macOS 키체인 "Safe Storage")
- 빌드본에서는 월페이퍼가 asar 안이라 폴더에 넣어도 안 보임 — 필요하면 userData 폴더도 같이 스캔
- 위젯 데이터의 `theme: 'LIGHT'|'DARK'` 필드가 미사용 — 지우려면 스키마 마이그레이션 필요
- `src/spaces/backgrounds.ts`의 `isLightBackground()`는 dead code (테마의 `mood`가 대체)
