**첫 화면은 [Onboarding.tsx](../src/onboarding/Onboarding.tsx) 하나에 다 있다** — room / work / fill / chrome / tools / name. 빈 프로필로 처음 켜면 뜬다. **개발 중에는 `npm run dev:fresh`** — 테스트 프로필(`focus-desk-test`)을 지우고 띄우므로 몇 번이고 처음부터 볼 수 있고, 실제 데이터와 안 섞인다.

**갈래별로 이름 짓는 순간은 한 번뿐이다.** 크롬 갈래는 [2]에서 창 이름을 직접 지었으므로 마지막 질문을 건너뛰고 바로 끝난다 — 다시 물으면 방금 고른 이름을 덮어쓴다. 툴 갈래만 마지막 질문을 받는다.

**크롬 갈래는 고른 창 개수만큼만 공간을 만든다.** 온보딩이 시작할 때 만든 빈 공간이 **첫 창의 공간이 된다**(`renameSpace`) — 옆에 빈 채로 남기지 않는다. 나머지 창은 `spacesFrom`으로 통째로 저장하고, `addSpaces`가 활성 공간을 자기 첫 문서로 바꾸므로 **바로 `setActiveSpace`로 되돌려야 한다**. 이걸 안 해서 메모·할 일이 엉뚱한 공간에 겹쳐 들어갔었다.

**임포트한 공간에도 사용자가 고른 방을 입힌다.** `takeRoom`의 `setTheme`·`setBackground`·`setAmbience`는 **활성 공간에만** 걸린다. 새 공간은 `newSpace()`가 기본 테마로 만들므로, `spacesFrom`에 넘기는 `blank`를 방으로 감싸야 한다(`roomSpace`). 안 그러면 공간마다 배경이 다르게 나온다.

**앞 4개 탭은 실제로 열고 나머지는 카드로 깐다** — [chromeImport.ts](../src/spaces/chromeImport.ts)의 `OPEN_TABS`·`importLayout`. 배치는 화면 셀이 아니라 실제 크기로 계산하고 카메라를 나중에 맞춘다 — 페이지가 카드보다 눈에 띄게 커야 하는 것이지 블록이 정확히 한 화면일 필요는 없다.
- **4개가 상한이다.** [Canvas.tsx:22](../src/canvas/Canvas.tsx#L22)가 활성 공간 위젯을 **전부 마운트한다** — 가상화가 없다. 열린 탭 하나 = 그 공간이 열려 있는 내내 잡고 있는 Chromium 렌더러 프로세스 하나다. 10개는 제일 좋아하는 공간을 제일 무거운 공간으로 만든다

**파비콘은 카드가 스스로 받아온다** — AppleScript는 파비콘을 못 읽는다. 아이콘 없는 카드가 마운트될 때 `images:favicons`를 부른다. **임포트할 때 미리 받는 방식이었다가 고쳤다** — 받는 데 1~2초 걸리는데(youtube 980ms, airbit 1.7s) 그 전에 버튼을 누르면 빈 채로 만들어졌다. 카드가 부르면 레이스가 없고, 크롬 패널로 나중에 가져온 카드에도 붙는다. main이 **호스트당 요청 하나**를 캐시하므로 한 사이트 탭 12개가 1번만 받는다

**아이콘 받는 순서와 이유** ([images.ts](../electron/ipc/images.ts)): **페이지의 `<link rel=icon>` 중 제일 큰 것** → 없으면 `/favicon.ico`. `/favicon.ico`가 보통 32px라 64px 로고 자리에서 뭉갠다(github·notion 확인). **아이콘 서비스를 안 쓴다** — 사용자가 연 사이트 목록을 남에게 넘기는 게 이 앱이 할 짓이 아니다

**카드는 아이콘에서 뽑은 색으로 자기를 칠한다** — `faviconColor`(`r, g, b`). 픽셀을 **채도로 가중평균**한다. 단순 평균은 어두운 배경 위에 그린 로고가 그 배경색으로 나온다(Figma가 `33,29,34`로 나왔다 — 배경과 구분이 안 됐다). 채도가 거의 없는 로고는(GitHub의 검은 마크) 단순 평균으로 떨어져 회색을 받는다 — 그게 사실이다. 색은 main에서 뽑는다: 아이콘이 커스텀 스킴으로 오므로 렌더러 canvas가 오염돼 픽셀을 못 읽는다

**G와 F는 서로 다른 것을 움직인다.** **G = `arrangeWidgets()` — 위젯을 옮기고 크기를 바꾼다. F = `fitToWidgets()` — 카메라만 움직인다.** 예전 [ShortcutSheet](../src/app/ShortcutSheet.tsx) 라벨이 "Arrange"·"Fit"이라 아무것도 설명 못 했다. 소리가 비슷하고 하는 일이 전혀 다르므로 **라벨에 차이를 쓴다**

**`z`는 만든 순서가 아니라 쓴 순서여야 한다.** `addWidget`이 `z = topZ + 1`을 주므로 **마지막에 만든 게 제일 최근 것**이 된다. 온보딩은 메모·할 일을 마지막에 넣었고, 그래서 focus 정렬이 **한 번도 안 건드린 빈 메모에 제일 큰 타일을 줬다.** `layOut`이 끝나고 `orderWidgets(made)`로 다시 매긴다 — 사용자가 보고 있던 탭이 먼저, 메모·할 일이 마지막

> 비율이 이상해 보이던 것도 같은 원인이었다. 세로로 긴 메모(420×460)가 2×2 타일에, 가로로 긴 브라우저(900×620)가 1×1 칸에 들어가면 각자 비율을 지키느라 2배로 안 보인다. 큰 타일 2개가 같은 종류가 되면 2.1배가 그대로 읽힌다

**방을 고를 때 한 번만 쓴다** — `setRoom(themeId, background, ambience)`. 예전엔 `setTheme`→`setBackground`→`setAmbience` 세 번이었는데, **`setTheme`이 `background`를 지운다.** 그래서 `SceneLayer`가 테마 자기 월페이퍼로 0.9초 크로스페이드를 시작했다가 중간에 진짜 월페이퍼로 다시 페이드했다 — 고른 적 없는 장면이 반쯤 보이는 게 그 깜빡임이다

**방으로 들어가는 연출** — 상수는 [Onboarding.tsx](../src/onboarding/Onboarding.tsx)의 `REVEAL_MS`(520)·`NEXT_STEP_MS`(150)·`SCRIM_BROWSING`(0.84)·`SCRIM_SETTLED`(0.4). CDP 화면 녹화로 잰 값:

| | |
|---|---|
| 0ms | 고른 카드 자리가 방의 최종 밝기로 밝아지면서 바깥으로 열리기 시작 |
| 140ms | 나머지 카드와 질문이 사라짐 |
| ~200ms | 화면 가득 |
| ~400ms | 다음 질문을 읽을 수 있음 |
| 760ms | 열린 사본이 밑의 방으로 페이드 — 그때는 같은 사진, 같은 밝기라 안 보인다 |

**핀치는 마우스 판정을 절대 안 거친다** — [useCameraControls.ts](../src/canvas/useCameraControls.ts). macOS가 핀치를 넘겨주는 모양이 마우스 휠 서명과 **정확히 같다**: `deltaX`는 항상 0, `wheelDeltaY`는 손가락을 얼마나 움직였든 항상 정확히 `±120`. 그래서 `looksLikeMouse`가 핀치를 전부 마우스로 봤다 — 실측 2026-09-01, 핀치 이벤트 142개 중 133개 통과.

결과는 **핀치가 세기와 무관하게 이벤트당 딱 10%씩 계단으로 뛰는 것**이었다. 3px를 움직이나 22px를 움직이나 `Math.pow(1.1, ±120/120)`이 나온다 — 미세 조정이 아예 없다. `wheelDeltaY`에는 세기가 안 들어 있고, 세기는 `deltaY`(−22.19 ~ 22.61, 소수점)에만 있다.

| deltaY | 그때 적용된 값 | 나와야 할 값 |
|---|---|---|
| 3.21 | ×0.909 | ×0.968 |
| 13.76 | ×0.909 | ×0.871 |

고친 뒤 실측: 3.2px → ×1.033, 13.8px → ×1.148, 22.6px → ×1.254. 8월 27일 빌드와 같은 `exp(-deltaY*0.01)`로 돌아왔다.

> **두 손가락 스크롤(패닝)은 멀쩡했다.** 같은 로그에서 스크롤 이벤트 167개 중 오판 0건. 주석이 걱정하던 "deltaX가 0인 트랙패드 이벤트"는 실제로 문제를 안 일으켰다 — 문제는 핀치 한 갈래였다

**브라우저 위젯 위에서는 캔버스가 휠을 못 본다** — `<webview>`가 먹는다. 줌·패닝을 시험할 때는 빈 바탕에서 해야 한다

**브라우저 UA에서 토큰을 둘 다 뗀다** — [main.ts](../electron/main.ts). Electron 기본 UA에는 Chrome이 안 보내는 토큰이 **둘** 붙는다: 앱 자기 `<이름>/<버전>`과 ` Electron/<버전>`. D-095는 뒤엣것만 지워서 `focus-desk/0.1.0`이 남아 있었다. 지금은 둘 다 떼고 Chrome처럼 버전도 `<major>.0.0.0`으로 줄인다.

> **이걸로 Google 캡차가 없어지지는 않는다.** 2026-09-01 실측: 위젯이 `/sorry/index`를 받았는데, **UA를 하나도 안 바꾸고 다시 요청하니 그냥 통과**했다. 그 페이지는 요청이 어디서 오는지로 정해지지 UA로 정해지지 않는다. 여기서 한 건 앱이 책임질 몫만이다

**최대화는 창 전체를 덮는다** — [Canvas.tsx](../src/canvas/Canvas.tsx)의 `fullRect`. 예전에는 `canvasArea()`를 그대로 썼는데, 그 함수는 떠 있는 버튼 넷(사이드바 토글·타이머·소리·팔레트)이 앉을 위쪽 84px을 **항상** 뺀다. 그래서 최대화해도 위에 배경이 띠로 남아 최대화로 안 보였다. 지금은 그 84px을 도로 더하고, **버튼 넷이 최대화 동안 자기를 숨긴다**(`maximizedWidgetId !== null`).

> **AmbienceDock은 `hidden`으로 숨긴다 — 언마운트하면 안 된다.** 소리 엔진이 그 컴포넌트의 ref에 있어서 사라지면 소리가 끊긴다.
>
> **헤더를 창 드래그 영역으로 만들지 않았다.** 최대화하면 헤더가 타이틀바 자리에 오지만, macOS가 드래그 영역의 더블클릭을 자기 창 확대로 가져간다 — 헤더 더블클릭이 최대화를 푸는 방법이라 그게 깨진다. 대신 최대화 중에는 창을 못 옮긴다.
>
> **신호등 자리로 헤더 내용을 78px 민다**([WidgetFrame.tsx](../src/canvas/WidgetFrame.tsx)의 `TRAFFIC_LIGHTS_WIDTH`). `trafficLightPosition`이 `{x:10, y:10}`이고 버튼 세 개가 52px이다. 사이드바가 열려 있으면 그 모서리를 사이드바가 잡고 있으므로 안 민다.
>
> **게스트 폭은 이미 따라오고 있었다.** "최대화해도 페이지가 옛 폭"은 옛 버그다 — 2026-09-01 실측으로 640 → 1184로 다시 배치된다. 알려진 버그에서 지웠다.

**정렬 `focus` 모드 = 모자이크** — [layout.ts](../src/canvas/layout.ts)의 `focusGrid`. 앞 2개가 **작은 칸 정확히 2×2**를 차지하고 전부 같은 격자에 앉는다. 순서는 `arrangeWidgets`가 주는 대로 = **최근 쓴 순**(z 내림차순). 열 수는 상자들이 칸을 제일 잘 채우는 값으로 고른다 — 가로로 긴 브라우저 위젯이 세로로 긴 칸에 들어가지 않게

> **처음엔 "앞 줄이 높이의 58%"로 만들었다가 갈아엎었다.** 위아래 띠가 서로 무관해져서 거대한 타일 2개 밑에 작은 것들이 깔린 모양이 됐다. 비율도 숫자가 나오는 대로였다. **같은 칸의 정수배**로 하니 크기 차이가 2.1배로 줄고 세로선이 맞는다

**`grid`도 G도 안 건드렸다.** G는 `arrangeWidgets()` = grid 그대로다. `focus`는 ArrangeMenu·SelectionBar에서 눌러야 나온다. **한 번 G를 focus로 바꿨다가 되돌렸다 — 사용자가 고른 것은 "grid는 그대로 두고 세 번째 모드 추가"였다**

**온보딩 마지막은 투어가 아니라 한 줄이다** — 줌아웃이 끝나면 `“이름” is yours — make yourself at home. G tidies up, F fits it on screen.`가 뜬다. **사용자가 닫거나, G를 한 번 누르면 사라진다**([useKeyboardShortcuts.ts](../src/canvas/useKeyboardShortcuts.ts)에서 `dismissNotice`) — 가르치려던 키를 썼으면 그 줄은 할 일을 다 한 것이다. 버튼이 아니라 키 이름인 이유: 버튼은 지금 한 번을 해결하고 키는 내일을 해결한다. 6초 뒤 사라지면 그때 안 보고 있던 사람에게는 없는 것과 같다(`showNotice(label, action, sticky)`). 단계별 투어를 안 만드는 이유는 아래 "하지 않을 것"에 있다

**끝나는 방식이 이 화면의 핵심이다.** 온보딩이 사라진 뒤 위젯이 **하나씩** 자리에 앉고(110ms 간격), 그 다음 카메라가 가까운 데서 전체가 보이는 데까지 물러난다. 한꺼번에 나타나면 원래 있던 템플릿처럼 보이고, 하나씩 앉으면 자기 책상이 차려지는 것으로 보인다. 줌 제스처는 **다 본 다음에** 이름을 알려준다 — 시켜서 하는 동작이 아니다.

**"여기서 무슨 일을 하나요"는 설문이 아니다.** 답이 **세 가지**를 바꾼다 — 툴 그리드의 그룹 순서, 마지막 질문의 예시 문구, 그리고 처음 놓이는 할 일 목록(Design이면 "레퍼런스 모으기 / 1차 시안 / 피드백 요청"). 답이 아무것도 안 바꾸면 물어볼 이유가 없다. 고른 값은 `work-v1`로 저장한다 — **타겟 사용자가 아직 안 정해졌으므로 이게 유일한 실데이터다**.

**첫 실행은 빈 공간으로 시작한다.** 기본 공간에 메모·타이머를 넣던 것을 뺐다 — 온보딩 뒤로 비쳤고, 끝난 뒤에도 사용자가 고르지 않은 위젯이 남았다.

**앰비언스 값은 30 이상이어야 들린다.** 엔진이 `level / 100 × 0.25`로 매핑한다. 처음에 8~18로 넣었다가 "소리 안 난다"는 얘기를 들었다.

**아래 ①~④ 설명은 만들어진 것의 근거로 남긴다. 남은 것은 이것뿐이다:**
- **줌아웃은 이 공간의 위젯만 펼친다.** 예전 STATUS에 "모든 공간이 한 화면에"라고 적혀 있었지만 **캔버스는 활성 공간만 그린다**([Canvas.tsx:23](../src/canvas/Canvas.tsx#L23)) — 여러 공간을 한 화면에 놓으려면 새 기능이 필요하다
- **배경은 사용자가 첫 화면에서 고른다** — [rooms.ts](../src/onboarding/rooms.ts)의 방 5개. 방 = 테마(색) + 월페이퍼(선택) + 소리 + 어울리는 시간대. **월페이퍼를 갈아끼우면 이 파일만 고치면 된다.**
- **월페이퍼 파일명은 두 군데에 박혀 있다** — [rooms.ts](../src/onboarding/rooms.ts)와 [themes.ts](../src/themes/themes.ts). `public/wallpapers/`에서 지우면 ThemePicker의 "My wallpaper" 목록은 폴더를 읽으니 자동 반영되지만, 이 두 파일이 참조하던 것이면 배경이 깨진다. `lofi-room`·`fireplace` 테마가 실제로 이렇게 깨졌고 지웠다 — 테마는 이제 4개(golden-hour·rainy-night·snowfall·paper), 기본은 `golden-hour`
- 시간대에 맞는 방이 맨 앞 **넓은 카드**로 온다. 그중에서도 그림 있는 방이 우선 — 넓은 빈 그라데이션은 첫인상이 나쁘다

**원칙 세 가지**
1. 빈 캔버스로 시작하지 않는다. 이 앱은 아무것도 없을 때 가장 매력이 없다
2. 첫 화면부터 사용자 자기 데이터를 쓴다. 샘플 워크스페이스는 애착이 안 생긴다
3. 연습시키지 않는다. 줌·드래그·정렬은 필요한 순간에 한 줄씩

**① 크롬 탭 가져오기 — 가장 빠른 길이지 유일한 길은 아니다**

열려 있는 크롬 창과 탭을 읽어 목록으로 보여주고, **창 단위로** 고르게 한다.

```
Chrome에 창 3개, 탭 41개가 열려 있습니다.
☑ 창 1 — 12개 탭   [Figma, Notion, 클라이언트 A 브리프, ...]
☑ 창 2 — 8개 탭    [Gmail, 캘린더, ...]
☐ 창 3 — 21개 탭   [유튜브, 뉴스, ...]

탭은 크롬에 그대로 있습니다. 아무것도 닫지 않습니다.
```

- **"탭은 그대로 있습니다"는 첫 화면에 반드시 있어야 한다.** 탭을 잃는 건 실제 공포다. 읽기만 하므로 사실이기도 하다
- **창 하나 = 공간 하나.** 창을 여러 개 벌려 쓰는 사람은 이미 창으로 프로젝트를 나누고 있다. 그 구조를 옮기면 "공간이 뭔지"를 설명할 필요가 없다. 이름은 그 창에서 가장 많이 나온 도메인으로 제안하고 고칠 수 있게
- 가져오면 자동 배치 — 앞 2개는 열린 페이지, 나머지는 카드(`importLayout`)
- **AppleScript로 읽는다** — `tell application "Google Chrome" to get {URL, title} of tabs of windows`. 창→탭 구조가 그대로 나온다
- **권한 프롬프트가 "제어"라고 뜬다.** 그냥 만나면 무섭다 — 프롬프트 **전에** 우리가 먼저 설명한다: "탭 목록만 읽습니다. 크롬은 그대로 둡니다"
- **거부하면 재프롬프트가 안 된다**(macOS TCC). 시스템 설정 열기 버튼을 주고 웹앱 고르기로 자동 이동
- **탭 수 상한이 필요하다.** 창당 12개쯤, 나머지는 북마크 위젯 하나로
- 출시는 **크롬만**. Safari·Arc·Edge는 반응 보고

**①-b 안 가져오는 사람 — 같은 화면에 나란히 둔다**

건너뛰기 링크로 숨기지 않는다. 권한 프롬프트를 피하고 싶은 사람에게 도망갈 곳이 보여야 한다.

```
[ 크롬에서 가져오기 ]     [ 대신 쓰는 툴 고르기 ]
```

| 상황 | 보여줄 것 | 사용자 노동 |
|---|---|---|
| 크롬에 탭이 있고 가져온다 | ① 창·탭 목록 | 0 |
| 크롬이 없다 / 안 켜져 있다 / 싫다 | **자주 쓰는 웹앱 고르기** | 탭 3~6번 |
| 둘 다 싫다 | 공간 1개 + 씨앗 위젯(노트·할 일) → ④로 | 0 |

- 프리셋 34개가 이미 있다. 로고를 그리드로 깔고 3~6개 고르면 그게 위젯이 된다
- **크롬이 안 켜져 있으면 실패를 알리지 않는다.** 그냥 웹앱 고르기를 기본 화면으로 띄우고 임포트 버튼은 남겨둔다
- **임포트 결과가 4개 미만이면** 웹앱 고르기를 이어서 보여준다. 허전한 화면으로 끝나면 안 된다
- **나중에 하는 길이 있어야 한다.** 런처(K)와 사이드바에 "크롬에서 가져오기" 상시 항목

**② 배경과 소리** — 임포트가 끝난 화면이 첫인상이다. 배경은 8장 중 하나로 고정(고르게 하지 않는다). 앰비언스는 볼륨 낮게, 끄는 버튼은 눈에 보이게.

**③ 줌아웃 한 번** — 위젯이 화면 밖까지 깔려 있으니 자연히 하게 된다. 한 줄만 띄운다. 모든 공간이 한 화면에 펼쳐지는 장면이 제품 전체를 설명한다.

**④ 마지막 — 질문 하나와 행동 하나**

```
오늘 무슨 일을 하시나요?
[ 클라이언트 A 리브랜딩 ]  → 이 이름으로 새 공간이 생긴다
```
질문은 **하나만**. 답은 반드시 공간 이름이 되어야 한다 — 답하고 아무 일도 안 일어나면 질문을 위한 질문이 된다.

**하지 않을 것**: 순차 클릭 튜토리얼, 단축키 표, 위젯 종류 나열, 텍스트로 쓴 서사, 통계·포커스 세션(1일차엔 빈 그래프), 앱 위젯·접근성 권한, 온보딩 직후 피드백 요청(겪은 게 없어서 쓸 말이 없다 — 3회차 또는 3일차에).

**2회차가 진짜 훅** — 컨텍스트 복원은 두 번째 열 때 겪는다. 온보딩 마지막에 예고("내일 열면 이 화면 그대로예요"), 2회차 실행에 한 줄("어제 이 공간에서 2시간 34분").

## 5. 캔버스 축소 한계 + 컬럼 그루핑

### 5-1. 축소 한계
지금 `MIN_ZOOM = 0.1`([camera.ts:15](../src/canvas/camera.ts#L15)) 고정이라, 위젯 몇 개뿐인 공간에서 끝까지 축소하면 글자가 안 읽히는 크기가 되고 주위가 전부 빈 공간이 된다.

- 최소 배율을 **공간 내용에 맞춰** 정한다 — 위젯 전체가 화면에 들어오는 배율보다 더 축소되지 않게. 계산은 [layout.ts:286](../src/canvas/layout.ts#L286) 근처의 fit 로직을 재사용
- 하한은 유지 (`0.1`보다 작아지지 않음). 위젯이 아주 많은 공간에서는 지금과 같다
- 패닝 범위도 같이 볼 것 — 축소를 막아도 빈 곳으로 계속 밀어낼 수 있으면 같은 문제다

### 5-2. 컬럼 그루핑
위젯을 세로 컬럼에 담아 묶는다. 컬럼에는 제목과 개수가 붙고, 컬럼째 옮기면 안의 위젯이 같이 간다.

- 지금은 다중 선택으로 임시로만 묶인다([WidgetFrame.tsx:113](../src/canvas/WidgetFrame.tsx#L113)) — 저장되는 그룹 개념이 없다
- **먼저 정할 것**: 컬럼이 (a) 새 위젯 종류인지 (b) 위젯에 붙는 `groupId` 필드인지. 정렬(`arrange`)·`z` 순서·공간 저장 형식이 다 여기에 걸린다. **코드 쓰기 전에 사용자와 합의**
- 컬럼 안에서는 위젯이 자유 배치가 아니라 세로로 쌓인다 — 기존 드래그·리사이즈와 어떻게 섞을지가 제일 어려운 부분

## 확인 안 된 것

- **웹뷰 우클릭** — 링크 위(새 탭으로 열기·주소 복사) / 이미지 위 / 글 선택 후. 네이티브 메뉴라 CDP로 못 띄운다. **손으로만 된다**
- **빈 프로필 가져오기** (1번 끝난 기준). `mv ~/Library/Application\ Support/focus-desk{,.real}` → 앱 켜기 → ⚙ Import → `Added N spaces` → **Show them** → 공간·위젯·사진이 다 서는지. 끝나면 되돌린다. 코드·테스트는 통과했지만 실기로는 안 해봤다
- **빈 프로필 첫 실행에 접근성 프롬프트 없음** (2번 끝난 기준). 같은 빈 프로필에서 앱 위젯을 만들어 클릭. 스위치를 켜면 그때 뜨는지도
- **세션 패널의 로그아웃 버튼** (3번). 목록 거르는 조건은 실제 쿠키 저장소 3개로 확인했지만, `session:clear-site`가 `siteOf`로 묶이게 바뀐 건 손으로 눌러봐야 한다 — 실제 로그인이 지워지므로 아무 사이트에서나 하면 안 된다
- **UA 수정 후 Google 검색**. 위젯 UA에 `Electron`이 없는 건 확인했지만, "비정상적인 트래픽"·reCAPTCHA가 실제로 줄어드는지는 며칠 써봐야 안다
- **크롬 임포트 실기** — 창 2개 이상 골라서: 공간이 **딱 그 개수만** 생기는지 / 전부 같은 방 배경인지 / 앞 4개가 진짜 페이지로 뜨는지 / **줌아웃이 끝난 배율이 1.0인지**(위젯이 화면에 꽉 차야 한다) / 카드에 진짜 로고와 **사이트 색**이 붙는지(1~2초 뒤 나타난다) / 메모·할 일이 첫 공간에 안 겹치고 들어가는지 / 토스트가 안 사라지고 G·F를 알려주는지 / **G를 눌렀을 때 큰 타일 2개가 브라우저인지**(메모·할 일이면 z 순서가 틀린 것) / 방을 고를 때 배경이 한 번만 바뀌는지. 자동화 권한 프롬프트가 필요해서 손으로만 된다
- **focus 정렬을 위젯 종류가 섞인 공간에서** — 메모·타이머·브라우저가 같이 있을 때 앞 2개가 커지는 게 말이 되는지. 테스트는 크기·순서만 본다
- **패키징본 실사용 QA** (2026-08-23 빌드, `release/mac-arm64`). 접근성 권한을 새로 줘야 하고, dev 인스턴스를 같이 띄우면 안 된다 — 팝업·링크 / 앱 숨김 알림(늦게 돌아오는 앱이 있다) / 앱·웹앱 위젯 / 공간별 로그인

## 코드 위치

- **설정 패널** = [SettingsPanel.tsx](../src/app/SettingsPanel.tsx). 사이드바 맨 아래 톱니(⚙). 지금 `APPS`(앱 창 붙이기 스위치)와 `DATA`(폴더 열기·내보내기·가져오기) 두 섹션. **앱 전체 동작 설정은 여기로**
- **팔레트**([ThemePicker.tsx](../src/app/ThemePicker.tsx))는 외양. 맨 위 `ALL SPACES`(Paper·웹 다크)만 앱 전역이고 나머지는 이 공간 것
- **백업** = [backup.ts](../electron/ipc/backup.ts). 하루 1회 스냅샷(최근 5개, `userData/backups/<날짜>/`), 내보내기·가져오기. **가져오기는 id가 같으면 건너뛴다** — 같은 프로필에 되가져오면 "Nothing new"가 정상이다. 쿠키는 백업에 없다
- **앱 창 붙이기** = `prefsStore.attachApps`, 기본 `false`. 접근성 프롬프트는 헬퍼의 `place`·`windows` 두 곳에서만 뜬다([FocusDeskHelper.swift:391](../electron/helper/macos/FocusDeskHelper.swift#L391), [:518](../electron/helper/macos/FocusDeskHelper.swift#L518))
- **정렬 순서** = `z` 내림차순(최근 쓴 것부터). `arrange()`는 받은 순서대로 깐다 — 안에서 다시 정렬하지 않는다
- **첫 실행 판정** = `spaceStore.needsOnboarding`. 저장된 공간도 마이그레이션할 것도 없을 때만 true. 공간은 **비어 있게** 만든다 — 활성 공간이 없는 상태를 아무 데서도 다루지 않아도 되면서, 온보딩 뒤로 위젯이 비치지도 않는다
- **`load()`에 중복 실행 가드가 있다.** React가 개발 모드에서 effect를 두 번 돌려 기본 공간이 두 개 생겼었다
- **온보딩이 만드는 것** = ④의 답이 그 기본 공간의 이름이 되고, 배경과 앰비언스도 거기 붙는다. 크롬에서 가져온 창은 별도 공간으로 추가된다
- **온보딩 화면의 색은 토큰을 안 쓴다.** 사진 위에 얹히는 화면이라 `glass-panel`·`chrome-button-on`이 너무 옅게 나온다 — 흰색 알파를 직접 쓴다
- **테스트 프로필** = `npm run dev:fresh`. `focus-desk-test`를 지우고 `FOCUS_DESK_PROFILE=test`로 띄운다([main.ts](../electron/main.ts) 상단). 실제 프로필과 안 섞이므로 실사용 앱과 동시에 켜도 된다
- **세션 패널 필터**(3번) = [session.ts](../electron/ipc/session.ts)의 `isLoginCookie`, `siteOf`는 [browserAddress.ts](../src/widgets/browserAddress.ts)(main·렌더러 양쪽이 쓴다). 광고 도메인을 거르는 건 `SameSite=None` 조건이다 — `httpOnly`만으로는 204개가 60개로 줄 뿐 `doubleclick.net`이 남는다. 목록은 엄밀히 로그인이 아니라 **이 공간에서 실제로 연 사이트**에 가깝다 — 쿠키만 봐서는 로그인만 남길 수 없다
- **브라우저 위젯 UA** = [main.ts](../electron/main.ts)에서 `Electron/<버전>` 토큰을 지운다. 안 지우면 Google이 자동화 트래픽으로 보고 "비정상적인 트래픽"으로 막는다. `navigator.userAgentData.brands`는 여전히 `Chromium`이라 reCAPTCHA가 완전히 없어지진 않는다
