**17-4 기본안** (파이어폭스 "컨테이너" 방식)
- 기본은 모든 위젯이 로그인 하나("Shared")를 같이 쓴다.
- 다른 계정이 필요한 위젯만 위젯 머리 메뉴에서 이름 붙인 로그인 묶음을 고른다. 묶음 이름은 사용자가 정한다.
- 위젯 머리에 묶음 표시(색 점)를 단다. 위젯 마크 8색과 겹치지 않게 한다.
- 그 위젯에서 열린 새 탭(새 위젯)과 팝업은 같은 묶음을 따라간다. 위젯을 다른 공간으로 옮겨도 묶음은 유지된다.
- 공간 메뉴의 "Separate sign-ins" 스위치는 없앤다. 지금 켜져 있는 공간은 공간 이름으로 된 묶음으로 옮긴다. 기존 `persist:space-<id>` 저장소를 그대로 써서 로그인이 사라지지 않게 한다.

**왜 바꾸나 (사용자 지적, 2026-09-17)**
- 스위치를 껐다 켜면 로그아웃처럼 보인다. 실제로는 저장소가 바뀐 것이고 전용 저장소는 남아 있지만, 화면에 설명이 없었다.
- 구글 계정 전환은 구글이 새 탭으로 열어서 새 위젯이 뜨고, 원래 위젯은 그대로라 전환이 안 된 것처럼 보인다. 위젯 단위로 바꿔도 새 위젯이 뜨는 건 같지만, 새 위젯이 같은 묶음을 따라간다.
- 한 화면에 두 계정을 띄울 수 없다.

**미확인:** 유튜브가 로그아웃된 원인. 후보는 ① 스위치를 꺼서 공용 저장소로 바뀜 ② 오늘 UA 변경으로 구글이 세션을 끊음.

## 16. 로그인이 되게 — 최우선 (2026-09-17, 착수 대기)

**사용자 요구:** 앱 안 브라우저에서 로그인이 안 되면 브라우저를 쓸 수 없다. 무조건 되게 한다. 구글이 제일 급하다. 이게 13(봇 검사)보다 우선이다.

**증상:** 쿠키 없는 상태에서 구글/유튜브/지메일에 **새로 로그인**하려고 이메일을 넣고 다음을 누르면 `/v3/signin/rejected`로 가며 "브라우저 또는 앱이 안전하지 않을 수 있습니다"가 뜬다. 구글이 임베디드 브라우저(Electron)를 막는 것. "Google로 로그인" 버튼을 쓰는 다른 사이트도 같이 막힌다. 구글 계정이 아닌 로그인(X·링크드인 등)은 화면은 뜨지만 완료까지는 미검증.

**2026-09-17 재조사 결과 — 자세한 표는 [LOGIN-ISSUE.md](LOGIN-ISSUE.md)**
- UA가 진짜 크롬 모양(`Chrome/142.0.0.0`만)일 때 막힌다. 앱 이름이나 `Electron` 토큰이 있으면 이메일 단계는 통과한다(최소 Electron 창·앱 위젯 둘 다).
- 앱 UA가 크롬 모양이 된 건 9/1 `db66902`(앱 이름 토큰 제거)부터 → 깨진 시점으로 추정. 비밀번호 단계까지는 미확인.
- 크롬 142(Chrome for Testing)는 통과 → 버전 탓 아님. 크롬에서 `window.chrome` 항목을 전부 지우면 막힌다.
- **A로 고쳤다(미커밋):** UA에 `FocusDesk/<버전>` 토큰을 넣는다([main.ts](../electron/main.ts)). 앱 위젯에서 3번 모두 `/rejected` 없이 이메일 다음 화면으로 갔다. 팝업 창도 같은 UA다. 이메일 화면에 캡차("들리거나 표시된 텍스트 입력")가 떴는데, 같은 IP로 자동 시도를 반복한 탓으로 추정한다.
- 실제 계정 시도에서 2단계 "패스키로 확인" 화면이 로딩만 됐다 — Electron은 패스키 요청이 끝나지 않는다(측정). `disable-blink-features=WebAuth`로 페이지에서 `PublicKeyCredential`을 없앴다(미커밋). 구글이 이때 다른 방법을 바로 보여주는지는 미확인.
- 안 C(시스템 크롬 로그인 → 쿠키 이전)는 이 방식이 다시 막히면 만든다(2026-09-17 사용자와 정함).
- **남은 확인(사용자):** 실제 계정으로 비밀번호·2단계까지 로그인 / 다른 사이트의 "Google로 로그인" 팝업 / 구글 검색 등 봇 검사가 늘었는지.
- 아래 "해봤고 안 된 것"은 크롬 모양 UA끼리 바꾼 시도라 전부 막혔던 것이다.

**처음 조사 (2026-09-17 오전, gtest 쿠키 없는 프로필 + CDP)**
- 진짜 크롬(빈 프로필)은 통과 → `/identifier`. 이 앱은 `/rejected`. 재현 100%.

**이미 해봤고 안 된 것 — 반복하지 말 것**
- UA를 크롬 142/152로 바꾸기, `sec-ch-ua` 브랜드에 "Google Chrome" 넣기, Firefox UA: 전부 `/rejected`. 모두 앱 토큰이 없는 UA였다
- `window.chrome.app`/`csi`/`loadTimes` 채우기: `/rejected`
- 크롬만 보내는 `x-browser-validation`·`x-browser-channel`·`x-browser-year`·`x-browser-copyright`: **원인 아님.** 진짜 크롬에서 이 헤더들을 CDP로 떼도 통과했다
- 고엔트로피 client-hint 헤더(`sec-ch-ua-full-version-list`·`arch`·`bitness`·`platform-version`·`model`·`wow64`·`form-factors`)를 `webRequest.onBeforeSendHeaders`로 추가: 헤더가 실제 전송된 것(`requestWillBeSentExtraInfo`)까지 확인했는데도 `/rejected`. **이 방식은 폐기, 코드도 되돌렸다.**

**단 하나 남은 실마리 (새 세션은 여기서 시작)**
- 같은 client-hint 헤더를 **CDP `Fetch.continueRequest`(파이프라인 맨 끝)로** 넣었을 때는 한 번 `/identifier`로 통과했다. 그런데 `webRequest`로 넣으면(전송은 확인됨) `/rejected`. 차이가 뭔지 모른다. 후보: ① 문서(navigation) 요청에도 헤더가 필요한데 webRequest 게이트가 놓쳤나 ② 첫 응답의 쿠키/플래그 ③ webRequest가 넣은 값을 크롬이 뒤에서 정규화 ④ 헤더가 아니라 **TLS/JA3 지문** 차이일 가능성. 재현 스크립트: `scratchpad/glogin.mjs`(TARGET=app/chrome, VARIANT, MAJOR), `inject.mjs`(통과한 CDP 주입), `strip.mjs`(크롬에서 헤더 제거).

**현실적인 방향 (헤더로 안 되면 이쪽)**
- **C2 재검토:** 구글 로그인만 시스템 크롬에서 하게 한다. 문제는 시스템 크롬 쿠키가 앱 공간 저장소로 안 넘어온다는 것. OAuth 흐름을 쓰는 앱이 아니라 그냥 웹뷰라 이게 간단치 않다. 방법 조사 필요.
- 구글이 임베디드 브라우저 로그인을 정책으로 막는 것이라, **완전히 되게 하는 게 불가능할 수도 있다.** 그 경우 "이 로그인은 크롬에서 열기" 버튼(C1)이 차선.

**되돌린 상태:** client-hint 실험 코드(`electron/clientHints.ts`, main.ts 배선)는 전부 지웠다. A1~A3는 커밋됨. 15번(공간 메뉴)은 워킹트리에 미커밋.

- **앱 아이콘** = [make_icon.py](../build/make_icon.py)가 그려서 `build/icon.png`·`icon.icns`를 만든다. 색 상수 3개와 좌표만 고치면 다시 나온다. `electron-builder.yml`이 icns를 쓴다
- **백업** = [backup.ts](../electron/ipc/backup.ts). 하루 1회 스냅샷(최근 5개). **가져오기는 id가 같으면 건너뛴다** — 같은 프로필에 되가져오면 "Nothing new"가 정상이다. 쿠키는 백업에 없다
- **앱 창 붙이기** = `prefsStore.attachApps`, 기본 `false`. 접근성 프롬프트는 헬퍼의 `place`·`windows` 두 곳에서만 뜬다
- **기능 목록 위젯** = `TOUR_LINES`. 줄은 `TodoItem.hint`로 식별한다([types.ts](../src/spaces/types.ts)의 `TourHint`) — 텍스트로 맞추면 사용자가 글을 고치는 순간 깨진다

## 규칙

- git 명령은 사용자가 직접 실행 (CLAUDE.md 워크플로우)
- dev 실행 시 `unset ELECTRON_RUN_AS_NODE` 필요(VSCode 확장 변수)
- **같은 프로필로는 앱이 하나만 뜬다.** 두 번째는 로그에 `already running … quitting`을 찍고 꺼지고, 첫 창이 앞으로 온다. 확인용 앱을 같이 띄우려면 `FOCUS_DESK_PROFILE`을 다르게 준다
- **main 프로세스 변경은 Electron 완전 재시작이 필요하다.** 렌더러 새로고침으로는 옛 핸들러가 계속 돈다
- **dev 중에 md 파일을 고치면 vite가 페이지를 새로 고친다** — 온보딩 진행 상태가 날아간다. 확인하는 동안은 문서를 안 고친다
- **다른 세션이 `dev:fresh`(test 프로필)를 쓰고 있을 수 있다.** 확인용은 따로 띄운다: `rm -rf "$HOME/Library/Application Support/focus-desk-check" && FOCUS_DESK_PROFILE=check FOCUS_DESK_DEBUG_PORT=9333 npx vite` → CDP로 누르고 찍는다
